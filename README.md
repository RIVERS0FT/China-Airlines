## 运行与检查

Node.js >=22.12，沿用已锁定依赖。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

React负责界面、PixiJS负责航网、本地SVG负责机场和飞机。独立TypeScript核心负责订单、人员与时间事件，Dexie/IndexedDB负责主存档和备份，PWA负责离线缓存。无业务后端、账号、外部地图、在线字体或遥测。

生产输出dist/通过HTTPS静态托管或本地HTTP服务访问，不支持双击HTML。BASE_PATH=/China-Airlines/用于项目子路径构建。主分支合并后按已有Pages流程完整复验，再发布同一产物；需要可用站点配置和权限。源码合并与静态包生成不等于网站已经上线。

所有机型、雇用/售机价格、游戏单位和地图坐标均为本作配置，不用于真实航空导航或调度，与现实航空公司无关联。

## 航班运行增量

顶部机队入口打开运行表，筛选待命/飞行状态并切换飞机；飞行页和地图显示当前航班锁定收支，不因浏览其他机场重新计价。机库默认跟随当前查看飞机。保留独立空机场浏览；在运行表选择飞机会退出固定机场浏览，所有位置和金额仍由核心决定。详细边界见 [运行信息规则](docs/FLIGHT-OPERATIONS.md)，证据补充见 [逐项研究清单](docs/REPLICATION-MATRIX.md)。

## 能量预算增量

飞行每60秒需要1点，起飞按整数秒预留当前航段，能量不足不扣费、不起飞；自动或多段运输在后续能量不足时停在实际机场并保留客货。机库可以安排或取消地勤补能，补能中的飞机不会被列为待命。旧版在途航班不追扣，旧订单和资金不重算。

基础240点取自2016攻略示例，统一容量、按秒预留和120秒免费地勤补满是本作声明的基础档/适配规则，**不是全部原版车型或恢复数值已经还原**。证据与差异详见 [能量规则](docs/ENERGY.md)。包0.5.0、存档5、数据库结构1；更新前导出备份。

## 精简发航页

底部“地图”已移到最左侧，进入游戏后默认打开保留全局导航的航网浏览页。开始派航后再进入独立铺满屏幕的专注规划地图，顶部只有目的地/预计时间/净利润/成本；点击顶部目的地打开城市选择，“查看路线”包含逐段费用、交付、能量和自动往返。地图直接点城市按顺序选路，取消起飞返回进入前的飞机或机场；飞行中用“返回航班”。保存和经营规则不变。开始场景、双语与两种地图模式见 [开始、地图与本地化设计](docs/START-MAP-I18N.md)，发航交互详见 [路线规划设计](docs/ROUTE-DISPATCH-REFERENCE.md)。
