# 公司人才与关键纪事

## 候选名单

人才系统在 `talent` 根对象中保存候选名单、独立随机种子、候选编号、师承记录、公司事务状态和关键纪事，不复制 `career.employees`。飞行员、地勤专员及两部门经理四类岗位各保留 3 个候选。

打开面板、刷新、离线或切换语言不会推进候选随机流。录用命令先完成岗位、资金和编号检查，再创建唯一员工并替换该候选；失败操作不得扣费或推进任何随机种子和编号。候选 ID 与员工 ID 属于不同命名空间。

## 培养与师承

人员档案分任职、培养和履历。只有存在真实有效直属经理的专业培训成功后，才记录员工、经理、模拟时刻和达到的专业等级。管理培训、失败操作和无有效经理的培训不产生师承记录，也不增加第二套收益。

师承记录按员工及专业等级唯一，调岗、经理转任、续约和日常履历滚动不会改写。组织树只表示当前直属关系；师承只在档案中展示，不能伪造汇报关系。

## 公司事务与纪事

公司事务是只读建议，包括满足条件的晋升、有效经理带教和未覆盖机场的地勤分配。查看建议只导航到对应档案，实际收费和任命仍由核心命令再次检查。事务不自动弹窗、不暂停运输、不自动花钱，也不会在离线期间替玩家决定。

关键纪事每类最多保存一次：首次招募、内部晋升经理、两部门成形、首次有效带教、首次有记录的有偿运输。运输纪事只在到达事件中生成，时间取真实模拟到达时刻；空飞与自产物资不计。渐进推进和一次性离线推进必须得到相同结果。

## 界面和存档

组织页使用本地原创员工头像。个人外观由稳定 ID 决定，语言、刷新、装卸和离线恢复不改变头像。人员档案按需打开并独立滚动；任务中心可按需展开公司事务，机队可定位负责飞行员。地图保持挂载且不显示人员关系线。

当前 `version: 10` 存档必须包含完整人才状态，并严格验证候选唯一性、岗位分布、数值范围、员工引用、师承等级、事务签名和纪事时间。格式不符或数据损坏时拒绝导入且不覆盖有效主存档或备份。
