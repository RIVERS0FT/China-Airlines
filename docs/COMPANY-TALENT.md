# 人才市场与培养履历

## 人才市场与候选更新

人才系统在 `talent` 根对象中保存候选名单、独立随机种子、候选编号和师承记录，不复制 `career.employees`；当前存档还保留内部事务与纪事字段，界面范围见下文。飞行员、地勤专员、飞行部经理、地勤部经理和总经理五组岗位各保留 3 个候选，共 15 人。总经理候选使用 `department: company`、`role: manager`，不生成公司专员。

公司组织页的原“招募”入口改为“人才市场”，市场显示距下次更新的倒计时。候选在每个30分钟周期内固定，达到1800秒刷新边界时自动整批更新全部15人；每人使用新候选编号，随机结果沿用独立人才随机种子，不影响客货等经营随机流。已经雇佣的员工、合同、岗位和履历不随市场更新而改变。

市场同时展示五个岗位组，每组3张人物卡，取消“招募岗位”下拉框和全局底部招募区。各组标题显示岗位名称及已聘人数/岗位上限；人物卡直接显示姓名、头像、岗位、潜力、特长、招募费用（包含7天合同）、每7天续约薪资和自动分配目标，注明合同不自动续约。卡片使用独立内容区域而非选择按钮，不保留候选选中态；只有卡内招募按钮执行录用，岗位已满、没有可分配飞机或机场、资金不足的禁用原因也在卡内显示。点击组织树职位空槽进入市场时定位对应岗位组，不隐藏其他岗位候选。

刷新由核心模拟时间事件驱动，边界固定为全局经营时间 `n × 1800` 秒；正常在线模拟时间与真实时间1:1推进，不以打开市场或人才系统起始时刻重新计时。打开或关闭市场、刷新网页、切换语言不额外推进候选随机流；离线期间只按实际推进的时间跨越刷新边界，沿用最多8小时离线补算与墙钟回拨不倒退规则。跨多个周期时按每个边界顺序更新，渐进推进与一次性离线推进必须得到相同候选、种子和编号。倒计时只读取核心下次刷新时刻，不靠界面计时回调重抽。

录用命令先推进到当前时间，再完成岗位人数、可分配资产、资金和候选编号检查；创建唯一员工、扣费、自动分配与补位该名候选作为一次命令完成，其余候选在该周期内保持不变，整批倒计时也不重置。无空位或人数已满时拒绝录用且不扣费。到达刷新边界时先完成免费整批更新，旧候选编号随后失效；迟到的录用请求必须拒绝且不扣招聘费、不新增员工，也不额外生成候选或推进随机流和编号，已发生的时间推进和定期刷新仍保留。候选 ID 与员工 ID 属于不同命名空间。

所有招募入口都改为录用即上岗，不再新增待分配人员。飞行员按机队顺序绑定首架未绑定员工且允许调岗的飞机（未飞行、无自动值勤与后续航段、未补能且地面周转结束），并开启该机飞行员标记；地勤按已开放机场顺序绑定首座无地勤的机场；经理占用相应唯一槽位。过期员工仍占位，原存档中的待分配人员保留，不自动迁移或重新分配。新专员有本部门经理时自动直属该经理，否则玩家直管，其他专员的汇报关系不变；总经理任命的部门经理直属规则仍按下文处理。具体资产条件见 [公司组织](COMPANY-ORGANIZATION.md)。

总经理录用即占用唯一总经理槽位，费用为 2,400 金币加 4 点券，含 7 天合同；初始专业 2 级、管理 1 级，潜力和特长取自市场当前已保存的候选。录用后只补位总经理组的该名候选；岗位已满时仍显示该组名单并参与定时更新，但不可再录用。任命时现有部门经理自动直属总经理，此后招募或晋升的部门经理沿用该规则。

## 培养与师承

人员档案分任职、培养和履历。只有专员在真实有效的本部门直属经理带教下完成专业培训，才记录员工、经理、模拟时刻和达到的专业等级。管理培训、失败操作和无有效经理的培训不产生师承记录，也不增加第二套收益。总经理和部门经理之间仅保存汇报关系，不产生跨部门培训折扣或师承记录；总经理可按既有规则自费培训和续约。

师承记录按员工及专业等级唯一，调岗、经理转任、续约和日常履历滚动不会改写。组织树只表示当前直属关系；师承只在档案中展示，不能伪造汇报关系。

## 当前界面与保留字段

公司组织页已移除“公司事务”和“公司纪事”的入口及专用面板、员工头像事务提示标记；任务中心也不再提供公司事务折叠区。玩家通过组织树打开员工任职、培养和履历，直接进行分配、培训、晋升和续约；人才市场招募及机队负责飞行员跳转继续保留。

本次只移除对应界面，`talent.deferred` 和 `talent.milestones` 仍属于 `version: 16` 的完整存档结构，继续保存和严格校验，不清空、不更换版本，也不恢复这两个功能的玩家入口。核心事务计算与纪事记录规则保持原样，不自动花费、任命或替玩家操作。

保留的内部纪事每类最多记录一次：首次招募、内部晋升经理、两部门成形、首次有效带教、首次有记录的有偿运输。总经理录用可成为首次招募，但不算内部晋升；“两部门成形”只计算飞行部与地勤部，公司总经理不能替代其中任一部门。运输记录只在到达事件中生成，时间取真实模拟到达时刻；空飞与自产物资不计。渐进推进和一次性离线推进仍须得到相同记录，不对玩家展示公司纪事面板。

## 界面和存档

组织页使用本地原创员工头像。已雇佣员工的外观由稳定 ID 决定，语言、刷新、装卸、离线恢复和市场更新不改变其头像。组织树顶部显示真实总经理或招募空槽；点击总经理空槽打开人才市场并定位总经理候选组，录用操作在相应人物卡内完成。组织树默认聚焦全部，使用无滚动条的缩放平移画布；删除独立待分配人员区域，原有未分配员工仍显示在所属部门树中。人员档案按需打开并独立滚动，保留任职、培养与个人履历；机队可定位负责飞行员。总经理与人才市场相关交互使用中文与英文本地化。地图保持挂载且不显示人员关系线。

当前 `version: 16` 存档必须包含完整人才状态，并严格验证 15 个候选的唯一性、五组各 3 人的岗位分布、数值范围、员工引用、师承等级、事务签名和纪事时间。下次刷新从现有 `simTime` 计算，更新使用现有种子和候选编号，不新增存档字段或版本；已有当前格式存档的名单保留到下一个整半小时边界。若候选编号空间不足以生成完整15人，则保留当前完整名单并停止整批刷新，模拟时钟继续推进。旧 `version: 13`、其他格式版本或数据损坏时拒绝导入且不覆盖有效主存档或备份；不迁移旧候选名单，IndexedDB 结构版本仍为 1。

## 公司业务增量经营

新增城市业务团队、真实每秒净收入、招聘、岗位扩建和业务培养，规则与数值见 [公司业务](COMPANY-BUSINESS.md)。业务员工使用既有唯一员工名单，岗位不计入运输人员15人限制。仅前台时段累计业务净收入，不新增离线业务奖励。当前存档v16必须包含business完整状态；旧v14及其他版本拒绝，不自动迁移、不覆盖主档或备份。
