## 唯一任务入口

机场场景左上角永久保留“任务”入口，首行显示实际可领取数量，第二行优先显示可领取任务，否则显示进行中的任务及进度。无任务时仍能打开记录；不另设未读红点。首航未完成时其摘要继续使用真实引导进度；可领取奖励优先，不冒充首航奖励。

删除底部“运营任务”及场景右侧“航班/改装/奖励”，不增加“更多”替代按钮。底部普通入口依次为地图、机场装载、机场目录、机队管理、飞机商店、公司组织、经营中心；机场页右下保持制定路线，共八个按钮。地图浏览页只显示七个普通入口。

任务中心统一展示原运营任务、成长任务、每日运输、七日启航礼、六区挑战，提供可领取/进行中/已领取筛选和奖励、进度、限制理由。有奖励时默认可领取，否则默认进行中。每日已领记录可回看；不补发已过期每日任务或签到礼，第七份礼的键与资格完全沿用核心。领取成功才改变金额、状态和数量，已领不可重复领取；关闭保持机场/飞机选择。领取后焦点返回当前筛选页签，原卡移至已领取。

经营中心不再重复展示“经营任务”页签。物资商店的投资赎回、物流园的贸易提交是消耗/交换型经营命令，仍留在相应业务页，不作为可领取任务计数。航班交付收入仍自动入账，不改为手工领奖。

## 机队管理

单一机队管理面板有“飞机/航班”两个页签。底部入口默认飞机，顶部机队概况及飞行机体快捷入口默认航班。航班页复用原清单的搜索、状态筛选、锁定金额和航段；点击一条航班打开对应飞机详情，点击“前往这架飞机”才关闭面板并前往实际机场/航班，避免浏览列表就改变场景。

飞机列表与详情显示状态、机场/航线、真实载荷和剩余时间；机上清单只读。改装、补能、随航调度员、出售继续在飞机详情内，通过原命令执行，原限制和费用不变。浏览、切换页签和查看航班均不得写经营状态。飞行中的机上清单仍标“已装机”，只禁止卸载。

## 客货三态

保留目的地分组、独立站牌、真实单体/历史聚合订单和横向候运地面。人物/货物不包进整块面板；保留小型状态底座。信息牌由原四级收敛为两行：价格（贸易物资显示名称）和一条装卸提示，不再重复叠加状态徽标、业务类型与动作按钮。

- 待装机：蓝色底座，提示“装机”。
- 已装机：绿色底座，提示“已装机 · 卸载”；补能等限制时显示“已装机 · 补能中”，保持真实装载状态。
- 不可装：灰色底座、插画降饱和度，直接显示“客舱不足”等具体原因，省去“不可装”前缀；完整原因保留在无障碍名称和悬停说明中。

状态不能仅靠颜色。中转仅显示“中转”，历史聚合单只保留实际数量（如“15人”“20吨”），单体订单不重复显示1。业务类型保留在无障碍名称和悬停说明，贸易物资不重复写名称及“运输入库”。目的地只在左侧站牌显示城市和机场代码，省去站牌“装机”字样；批量装载功能、可访问名称和说明仍保留。

不额外创造“未装机”存档字段；UI 根据真实订单位置先判断是否属于当前飞机，再调用已有装卸限制投影。异步保存暂时禁用操作并显示“保存中…”，不伪造容量不足。实际命令仍由核心重新验证。精简后的两行保留最多两行原因的空间，避免不同状态的图文重叠或装卸时位移。

装卸后原位变更，不能按状态立即重排；顶部载荷、机身示意及其他可装对象同步更新。目的地批量按钮无可装对象时不可点击，仍按核心批量规则装载。列表拖动或滑动不得触发误装卸；键盘激活不被之前的拖动吞掉。插画不得变成可拖拽图片。

## 装卸反馈静默（2026-09-14）

单个装机（load）、卸载（unload）和同目的地批量装载（load-destination）成功后，不再把经营日志作为底部浮动提示显示，包括“JB…已卸至北京，等待转运”“已装机”等同类常规装卸消息。反馈仅使用客货原位状态、顶部数量及机身示意，不新增弹窗、动画或确认步骤。

控制器在命令执行且存档事务成功提交后，将上述操作的 notice 置空，同时清除上一条仍在显示的成功提示；按命令类型判断，不按订单编号、城市或文案匹配。新手引导原有的静默行为保持。经营日志、订单位置、中转、收益与存档内容均不删除或改写，失败命令仍走原错误通道。

不全局隐藏 toast，不改动错误提醒、存档冲突阻断、导入与备份恢复提示，以及购买、领奖等其他操作的成功反馈。

## 机场导航图标与悬浮文字（2026-09-13）

机场底部七个普通入口和右下“制定路线”继续使用现有原创本地图标，不复制参考游戏素材。公司组织复用现有原创人员头像作为入口图标。图标作为按钮的第一视觉主体，功能名不再占据独立文字行，而是绝对定位覆盖在图标下部前景；文字使用高对比浅黄/白色、深色描边与投影，必须在明暗图标和选中/禁用状态上保持可读。悬浮文字不接收指针事件，不能改变按钮实际命中区域、键盘焦点或无障碍名称。

普通入口保持地图、机场装载、机场目录、机队管理、飞机商店、公司组织、经营中心的固定顺序。桌面默认尺度下图标约占按钮高度的三分之二至四分之三；右下“制定路线”保留最高操作优先级，但由180px宽横向按钮收敛为独立大图标入口，宽度明显小于旧版，图标和文字仍采用同一叠层关系。禁用原因不替代主标题，也不得隐藏主图标；允许以按钮上缘的小型状态提示显示，同时完整理由继续通过 title/aria-describedby 暴露。

短横屏沿用同一 DOM 和同一叠层结构，只按逻辑尺寸缩小图标与文字；不得重新按设备像素切换另一套导航。75%–150% UI 缩放下文字必须保持单行、不截断、不超出按钮命中区域，制定路线始终位于最右侧且视觉优先级高于普通入口。

## 验收与边界

新增任务投影/领取资格、区域前置、每日记录及七日键、装载优先级、满载释放、服务/飞行禁用与只读测试。浏览器覆盖入口唯一、领奖去重/刷新、完整飞机/航班跳转、三态并列与具体原因、卡片原位更新、拖动与键盘、底部导航图标文字叠层、横屏及UI缩放；旧业务测试仅迁移真实入口和状态文字，不删除结算、存档、部署或离线断言。

装卸静默回归在1440×900、844×390、667×375验证：单个装机、卸载、批量装机均即时检查无 toast，刷新仍保留载荷，购买成功提示仍可见，随后的静默装卸清除旧提示；保留旧存档导入导出及飞机切换断言。无提示断言不得靠等待旧提示的四秒超时来通过。

导航整合回归严格检查八个按钮及其顺序、离线状态下八个导航图标（含公司组织与经营中心）、七个普通入口的图文叠层；任务奖励的点券断言改读顶部 tickets-count，领取后及刷新后均检查余额，底部经营中心仅显示名称。装卸三态与离线装机流程直接断言无 toast，不再手动关闭提示来掩盖回归。原有离线图片解码、领取去重和持久化断言继续保留。

以1440×900、844×390、667×375浏览器视口及既有同比例、缩放、竖屏回归为准。真实手机硬件验收尚未完成。测试结果和部署回执以实际流水线为准，不以静态审查代替。
