# 机场主页移动游戏化视觉强化

后续覆盖：2026-09-12 按用户最新要求改用无卡片客货区、底部导航右下角发航按钮和常显机体载荷示意，具体见 [AIRPORT-REFERENCE.md](AIRPORT-REFERENCE.md)。下文的单体卡和桌面宽横向按钮描述不再代表当前界面。

本轮依据用户提供的《中华铁路》车站界面截图及随后确认的航空化视觉方向，只强化机场装载主页的视觉层级，不修改经营公式、客货订单、存档结构、发航地图或离线结算。

## 参考边界与冲突处理

参考图包含多种付费货币、礼包、排行、活动入口等内容，但当前 `docs/DESIGN.md` 明确要求暂不添加未经核实的原版付费货币，`AGENTS.md` 也要求未确认功能不得伪装成一比一复刻。因此本轮只借鉴“高密度顶部资源、场景中心大载具、下方候运队列、右下强起飞入口、亮色按钮”的视觉层级；不新增钻石、票券、声望等虚构经营资源，也不复制参考图的商标、图片、角色、按钮图标或美术素材。

现有真实信息继续作为唯一数据来源：运营资金、机队数量、完成航班、机场/飞机状态、客货容量、能量、候运订单和存档状态。没有数据来源的区域不显示伪数值。

## 机场主页层级

桌面横屏采用四层结构：顶部 HUD、浮动机场/飞机状态、机场场景、候运与底部导航。顶部 HUD 使用更接近移动经营游戏的高对比蓝色玻璃质感，品牌区与真实资源计数器形成独立圆角块；帮助与存档仍是原操作，不新增第二套状态。

机场状态条继续浮在场景上方，不重新占用独立大行。登机口、飞机状态、旅客/货物/能量保持可读，并使用半透明浅色面板与更强阴影。场景中的飞机仍是最大视觉主体，地面状态继续贴合既有跑道基线；只提高背景饱和度、层次和机体阴影，不改变飞机命中区域或飞行状态逻辑。

候运区继续一张卡对应一位旅客或一吨新货物。强化工具条、标签、目的地牌、收益与状态胶囊的层级，但不重新聚合订单。候运/机上切换、筛选、同目的地装载、横向翻页与键盘行为全部沿用现有规则。

底部导航改为更明显的蓝色圆角功能块，当前页用金色强调。桌面右下“制定路线”改为宽横向橙色主行动按钮，视觉优先级高于普通导航；844×390 与 667×375 等短横屏仍保留现有紧凑浮动按钮和队列右侧安全区，避免遮挡翻页或订单卡。

## 发航界面不变

`dispatch-focused` 独立发航页继续完全遵守 `docs/DESIGN.md` 与 `docs/ROUTE-DISPATCH-REFERENCE.md`：顶部四读数、连续地图、左下局部操作、右下唯一检票起飞。机场主页的移动游戏化皮肤只作用于 `:not(.dispatch-focused)`，不得把机场主页资源栏或底部导航带回发航地图。

## 响应式与验收

桌面 1440×900 重点检查顶部真实资源、浮动状态、完整飞机、单体客货卡和宽横向起飞按钮同时可见；844×390 与 667×375 继续检查触控命中、订单状态至少 11px、客货翻页不被起飞按钮覆盖、页面无水平溢出。竖屏提示、离线、存档、导入导出与经营回归不因本轮视觉修改而改变。
