# 本地化架构

## 目标

本地化属于 UI 展示层，不进入 `src/core` 的经营状态、命令、存档键或数据库结构。核心继续保存稳定机场 ID、机型 ID 及既有经营数据；语言偏好只保存在浏览器 `china-airlines:locale:v1`，导入存档、恢复备份和重新开始不得改写该偏好。

当前正式支持 `zh-CN` 与 `en-US`，默认 `zh-CN`。新增语言必须以“注册一个 locale bundle”为主要工作，不允许在 React 页面、格式化函数、实体名称函数中增加 `locale === ...` 的分支。

## 目录与职责

- `src/i18n/locales/<locale>.ts`：该语言的语义消息、页面 metadata、机场/机型/洲名及搜索别名。
- `src/i18n/registry.ts`：唯一的正式语言注册表、默认语言、受支持语言校验与回退。
- `src/i18n/format.ts`：数字、经营货币和时长格式化；货币单位仍为游戏经营使用的人民币符号，不随界面语言改币种。
- `src/i18n/entities.ts`：按稳定 ID 读取本地化机场、机型和洲名，并汇总所有已注册语言的机场搜索别名。
- `src/i18n/I18n.tsx`：薄 React Context；负责偏好保存、`html.lang/dir`、页面标题/描述和向组件暴露统一 API。
- `src/i18n/compat/core-text.ts`：只读翻译核心历史中文日志/错误；未知文本原样回退，不修改存档。
- `src/i18n/compat/legacy-ui.ts` 与 `legacy-en.ts`：尚未迁移到语义 key 的旧 UI 兼容层。新 UI 不得继续把中文显示文本当作正式 key。

## 消息键

`zh-CN` 是语义消息 schema 的类型来源，其他正式语言必须满足完全相同的 `MessageKey` 集合。组件使用：

```ts
const { t } = useI18n();
t('airport.name', { city });
```

不得在新增界面中使用 `ui('中文原文')` 作为新接口。旧页面可逐模块迁移，兼容层在迁移完成前保留。

不同语言同一 key 的 `{placeholder}` 集合必须完全一致；测试对所有正式语言自动校验。

## 实体目录

机场、机型和洲名按稳定 ID/稳定源值查找。翻译后的展示名不能作为命令、存档键或经营身份。

机场搜索由核心目录名称、机场 ID/区域和 `airportSearchAliases()` 提供的已注册语言别名共同组成。新增语言的机场实体加入 bundle 后即可自动进入别名集合，不修改机场搜索实现。

缺失实体翻译时使用调用方传入的核心名称作为 fallback；不得因缺少翻译阻塞存档或经营逻辑。

## 新增语言流程

1. 新建 `src/i18n/locales/<tag>.ts`，提供 `meta`、完整消息表和需要的实体目录。
2. 在 `localeRegistry` 注册该 bundle；`Locale`、语言选择器、偏好校验、metadata 与格式化自动取得新语言。
3. 为仍通过兼容层展示的旧 UI/历史核心文本按需补充该语言兼容翻译；缺失时允许回退原中文，但正式语义 key 不允许缺失。
4. 运行类型检查、单元测试、生产构建和 Playwright；检查横屏布局不会因更长文案溢出。

## 回退与兼容

浏览器中保存了未知或已移除 locale 时回退 `zh-CN`，不修改游戏存档。正式语义消息不做逐 key 静默回退：缺 key 应在 TypeScript/测试阶段失败。实体名称与历史兼容文本可以回退核心中文，以保证旧日志、旧存档和经营数据始终可读。

当前改造不提升游戏存档版本（仍为 v9）或 IndexedDB 结构版本（仍为 1），不新增运行依赖，也不改变离线结算、经营数值或 PWA 首次缓存规则。
