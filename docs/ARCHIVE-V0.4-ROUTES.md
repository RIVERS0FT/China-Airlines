# 中华航空 · v0.4 机场浏览、航班运行与路线交互修订

状态：机场目录、独立候机大厅、到离港信息、锁定航班收支、机队运行清单，以及按城市点击顺序规划路线。沿用已合并的人员、售机、装载和航段预览，不将当前版本称为完整复刻。

## 1. 设计继承与边界

未修改的现行规则完整保留在 [ARCHIVE-V0.4-CREW.md](ARCHIVE-V0.4-CREW.md)。其中关于“单段/多段模式切换”“付费开通航线/计划航线”的旧规则被本文件第5节明确替换，不再作为现行玩法。机场浏览的详细交互、边界和测试按 [AIRPORT-BROWSING.md](AIRPORT-BROWSING.md) 执行；地图相机继续遵循 MAP-LAYOUT.md，客货队列和草稿表现继续遵循 UI-REFERENCE.md。

本轮扩充原来只能跟随飞机的主场景：默认仍跟随选中飞机，玩家主动进入机场时切换为固定机场浏览。无当地停靠飞机时显示空停机坪、只读客货，不能借用其他机场或在途飞机。除第5节明确修改的路线交互与航线建设费外，不改变机场/机型配置、人员费用、售机残值、订单刷新/报酬、运输耗时和存档结构。

完整复刻范围以 [REPLICA-COVERAGE.md](REPLICA-COVERAGE.md) 的证据—实现—差异清单逐项核对。原作封存、拆解组装、能量消耗、关闭站点等不得因现有售机或运营成本已经实现而标记完成。尚未固定准确原版客户端；目录与到离港界面是航空化工作流，未声称已完成像素级对照。

## 2. 不变约束

横屏、中文、2D、单机Web/PWA，TypeScript + Vite + React + PixiJS8 + Zustand + Dexie。无业务后端、账号、外部地图、在线字体、广告或遥测。素材原创。

src/core唯一写入经营状态；airport-presentation、地图草稿和路线预览只读取快照，绝不改位置或收益。界面上的解锁、升级和购机复用核心命令；关键操作保存成功后再显示结果。动画、目录访问和路线预览不付款、不补客源。

保留真实客货、最终目的地单次交付、8秒周转、最多5段有限计划、真实供给驱动自动值勤、安全售机、历史机队任务、最多8小时事件式离线推进与时间回拨规则。v1/v2/v3严格迁移为v4，导入失败不覆盖有效存档，事务备份/revision并发保护不变。

包版本仍0.4.0，存档格式4，IndexedDB结构1，依赖及锁文件不变。机场浏览/搜索/路线草稿均为临时UI状态，不新增存档字段，不要求重开游戏。

## 3. 操作与验收

目录 → 查看需求和到离港 → 进入任一已开放机场 → 选择当地停靠飞机、当地购机交付或规划调机 → 装载起飞。查看详情关闭后不得丢掉仍在地图上的草稿。实际起飞仍从飞机真实停靠机场出发，浏览空机场不能瞬移；飞机到达后才进入该机场地面列表，仍执行周转。

新增单元验证计量单位、中转归属、在途排除、到达切换、无飞机/失效选择和异地订单禁用；新增浏览器验证1440×900、844×390、667×375空机场、购机装载、实际出发地和草稿保留。保留全部旧断言，只有与第5节旧路线规则直接冲突的断言可以改写；不得以跳过或重试掩盖失败。类型检查、根/项目子路径构建与浏览器测试、截图复核及产物校验后，通过PR squash合并。

使用既有Pages流程复验并部署同一产物。站点/权限不足时如实记录，不改变仓库可见性、不购买服务、不上传密钥。源码或ZIP交付不等于上线；没有部署成功回执和可访问地址不得宣称上线。模拟视口不等于真实iOS/Android认证。

## 4. 航班运行信息与导航

[FLIGHT-OPERATIONS.md](FLIGHT-OPERATIONS.md)规定当前航班账目、运行状态筛选及只读导航。它补充而不替换机场浏览：空机场不展示异地飞机的账目；在运行表选择飞机退出固定机场浏览；飞行中浏览机场详情不改变在途目的地或锁定收入。机库优先选中实际查看的飞机。

合并时保留机场浏览全部测试，补充跨模式检查、航班收支和运行清单检查。固定机场、实际飞机和地图浏览目标必须分开，不通过访问清单装载、瞬移、派航、扣费或付款。

## 5. 路线选择与城市通航规则

本节替换旧设计中的“单段派航/多段计划”切换和“开通航线/开通计划航线”玩法。

地图只有一种路线编辑状态。飞机当前停靠机场是隐含起点；玩家依次点击已解锁城市，点击顺序直接形成第1、2、3……段路线。再次点击当前路线末端不重复添加；可以在经过其他城市后再次访问起点或先前城市。最多5段。界面只保留“撤销末段”和“清空路线”等草稿编辑，不再出现“单段派航”“多段计划”“添加某城市航段”模式按钮。

机场是否已解锁是能否前往该城市的基础经营门槛。城市已解锁且满足机型机场等级、航程、飞机状态和运营资金等既有条件时，可直接起飞，不再支付航线建设费，也不要求先创建一条可用航线。未解锁城市仍可在地图查看并执行机场解锁；解锁成功后可直接加入路线。

保存结构中的 `routes` 字段暂时保留以兼容v1-v4存档、在途航班的 `routeId` 和自动往返端点。它从“玩家购买的基础设施”改为“已实际使用/自动值勤的通航关系记录”：首次成功起飞或启动等待中的自动值勤时按需写入，不收费、不作为手动派航前置条件。旧存档已有routes原样保留，不退款、不重复收费；新玩法不再提供购买routes的界面。

一站路线等价于原来的手动单段派航；两站及以上路线仍使用有限计划的逐站到达、8秒周转、逐段扣运营费、只在订单最终目的地交付、不在途中自动补装规则。自动往返只允许恰好一个目的城市，并继续要求随航调度员、真实直达订单与原有自动值勤安全规则。

地图预览只说明航段是否可飞、访问顺序、成本和交付，不再出现“须先开通航线”“航线建设费”或“已开通”作为可飞条件。历史routes可用于绘制已运营网络，但不得让未运营路线变成额外付费门槛。
