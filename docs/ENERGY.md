# 飞机能量

## 证据与适配边界

第三方《中华铁路》攻略记录了“每运行一分钟消耗一点电量”，并举出 240 点可运行四小时的例子。当前航空版采用这一比例；起飞预留、地勤补满时长和统一机型容量属于本作的确定性适配，不宣称已还原参考游戏全部车型和恢复规则。

## 当前模型

```text
plane.energy = {
  availableSeconds,
  reservedSeconds,
  serviceUntil
}
```

每架飞机的基础电力点数来自当前机型目录，容量为 `机型电力 × 60` 飞行秒，并受电力强化影响。`availableSeconds` 与 `reservedSeconds` 都必须是安全整数，范围不能超过该飞机当前容量。UI 按 60 秒 = 1 点显示，存档和判断使用整数秒预算。

当前航段能量按整分钟预算：`max(1, floor(飞行秒数 / 60)) × 60` 秒。起飞时先检查全部经营约束；只有成功起飞才把该预算从 `availableSeconds` 转到 `reservedSeconds` 并扣除运行成本。到达时只清空预留，不再次消耗。空机也消耗能量；发动机改装缩短飞行时间，因此可能减少能量需求。

有限计划逐段预留。首段能量足够即可执行；后续航段不足时停在实际机场，保留机上订单并终止剩余计划。自动值勤首次起飞失败必须原子回滚自动装载，后续不足则保留当前真实载荷并停止值勤。

## 地勤补能

只有地面、周转完成、无自动值勤、无待执行计划且能量未满的飞机可以开始补能。开始补能只设置 `serviceUntil`，不会立即加能。基础服务时长为 120 模拟秒；地勤人员能力可以缩短新服务的时长，已经开始的截止时间不追溯改变。

补能期间禁止装卸、起飞、改装、人员调整和售机，但可以浏览、取消补能或操作其他飞机。截止事件只执行一次，补满后不扣金币、不改变订单或运输统计，也不自动重启值勤。取消只清除截止时间并保留原余额。

补能由核心模拟时间推进。刷新、打开机库、修改系统时区或主动导入都不能直接完成补能；普通离线恢复受最多 8 小时推进上限约束。

## 严格校验

当前 `version: 10` 存档必须包含精确能量字段。负数、小数、非有限数、超容量、无航班却有预留、预留与航班预算不一致、服务和飞行或自动计划并存，以及非法服务截止时间都会拒绝。仓库没有旧能量格式的迁移器或测试夹具。
