# 原剖面直排与统一飞机画布（2026-09-16）

本次按用户确认实施，替换旧设计中的固定56%/44%分舱、重复绘制墙壁/地板、外壳独立缩放和家具随乘客尺寸变化规则。经营、实际容量、真实订单、存档v9、数据库v1与结算全部不变。

制定航线、检票起飞分别固定在所在页面右下方，共用右侧间距、底部间距和高度。其他导航及路线工具保持左对齐。禁用状态、警告和中英文文字不改变按钮位置。透明底部容器不接收指针事件，仅具体按钮接收。

飞机只使用原剖面中的墙壁、舷窗与地板。不再绘制第二套舱壁、地板、矩形内部底色或前沿边框。客货直接放在各机型原画布的测量点上；上下层位置按原图标定，不通过分舱比例覆盖原图。纯客运/货运仍只显示一个对应经营舱室，不因底图中的额外结构产生新容量。

全部图层共享1536×590画布、同一原点、同一等比例缩放。只由飞机根节点测量可用区域；订单和每舱不再分别观察尺寸。家具尺寸由六种乘客的共同安全包围范围预先确定，空座与不同乘客不能改变座椅。人物臀部接触坐垫、脚底接触地板；货物底部接触托盘。透明裁切容器只限制家具与客货的绘制范围，不绘制背景。

每款机型使用固定数量的可见摆放点，容量较大时分页，窗口缩放不改变每页订单集合。家具节点按位置保留，末页不足的位置只隐藏并停用，不生成空位文字或额外经营容量；装卸及换页不创建/销毁家具。切换外观不卸载内部节点或清空分页；被外壳遮挡的内部同时隐藏并设为inert，保留再次展开时的订单身份和键盘状态。文字使用家具旁的透明信息区，不挤动地板或家具；机舱侧边文字区高30逻辑像素，整个订单点击区域至少44逻辑像素，分页控件保持44逻辑像素。短货舱的透明点击区可延伸至家具下方，但图像仍裁切在实际舱口内；它不产生地板、边框或新的内部视图。

家具最大右边界为摆放点宽度的58%，侧边文字从60%处开始、占40%，至少留出2%的间隔；空位文字采用同一边界。不能只校验人物或货物而漏掉座椅/托盘。全部13款机型在空载、装载、外观切换后及缩放后检查实际文字与家具/客货包围框，避免无背景文字仍压到家具上。

## 素材管线

`aircraft-canvas.json`是画布与历史图集裁切尺寸的唯一来源。原历史图集上部590行、下部434行，不再使用旧提示词中的512行假定。`prepare-aircraft-art.mjs`统一提取、注册与合成；PowerShell入口只调用此脚本。输出剖面、近侧外壳、完整外观都是同尺寸透明PNG；商店等静态外观由同一对图层合成。

现有13款使用已有源图集的一次性离线注册；旧nearBounds仅供构建脚本读取，运行时不得读取或单独拉伸外壳。此处理消除坐标和缩放来源不同造成的错位，但不会凭空修正原始绘画的透视差异。新绘制必须从同一母版导出两张同尺寸图，通过每款配置的master.cutaway/master.near读取，禁止另画一张完整外观。重画前应锁定机身轮廓、舱口、机翼根部与发动机连接点。

开发启动、单元测试、生产构建自动准备资源，无浏览器端重采样，也不新增依赖。`npm run art:verify`额外输出叠合检查图及哈希清单。验证要求涵盖全部13款的图层尺寸、原点、合成像素一致性、透明角和舱口覆盖，及根路径和Pages子路径的装卸、分页、外观切换、缩放、中英文与离线回归。合并前以实际测试结果为准，禁止将计划写成已通过。

机场装载操作提示保留为屏幕阅读器说明，不再覆盖画布下沿的客货容量与翻页控件。地图继续由 Pointer Events 处理选点和手势；仅在画布自身取消 touchstart 的兼容鼠标合成，避免短距离触控拖动后额外触发相邻导航，不拦截按钮自身或新增透明遮挡层。
