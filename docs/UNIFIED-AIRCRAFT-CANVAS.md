# 独立剖面图与外观图绘制规则（2026-09-16）

本规则替换“完整剖面底图 + 近侧蒙皮图层 + 运行时合成外观”的旧绘制方式。以后每架新飞机直接交付同一飞机的两张完整图片：一张剖面图、一张外观图。两张图独立显示，外观图不是遮罩，不能由剖面图和近侧蒙皮拼合，也不能另画成不同角度或不同比例的第二架机型。

当前首架样稿位于 `art/aircraft-pair-v6/`，参考 Diamond DA40 的单发低翼、长泡形座舱盖、T 尾、固定前三点起落架和细长机身等通用结构，游戏化容量为1客0货。DA40只作结构研究；资源保持原创蓝白金涂装，不含品牌标志、注册号、现实涂装或技术图纸。本样稿尚未写入机型目录，不修改经营容量、存档或结算。

## 成品与母版

每架飞机交付以下文件，均为真正透明的 RGBA PNG：

- `aircraft-{id}-cutaway-{revision}.png`：1536×590，完整左向剖面飞机。
- `aircraft-{id}-exterior-{revision}.png`：1536×590，同一架飞机的完整左向外观。
- 生成器原图、完整提示词、参考边界和容量声明保存在对应 `art/` 目录；原图不是运行资源。

若一次生成上下两架飞机的母版，两架必须完全分离，分别完整落在自己的区域内，再无损分离、统一可见宽度和基线后导出上述两张运行候选图。母版尺寸可以随生成器变化，不能把母版行高当成运行画布规则。处理后每张图只能有一个显著连通的完整飞机主体；跨过分隔区的另一架飞机残片、孤立噪点或背景碎片必须使验收失败或在可复现处理步骤中清除。

## 两图一致性

- 两图必须是同一机型、同一左向侧视角：机头、螺旋桨或发动机、座舱盖、机翼、起落架、尾翼与机身比例一致。
- 两图使用相同可见宽度、底部基线、轮廓粗细、蓝白金涂装、材质、光源和阴影方向。透明留白可以有少量差异，飞机不能裁边。
- 剖面图保留完整外轮廓、远侧结构和可操作内部空间；外观图保留完整封闭机身。切换外观时替换整张飞机图，不在剖面上覆盖第二张图。
- 外观图不能透出乘客、座位或货物；剖面图的驾驶舱不能被误画成额外客位。

## 容量与动态内容

- 剖面内部按目录基础载客、载货量画出恰好对应数量的客位/货位分区；0容量的舱室完全不画。1客0货样稿只允许一个空客位，不得出现货舱。
- 美术源保持空舱：不预画座椅、托盘、人物、货物、行李、金额、城市、标签或空位文字。家具、真实订单、金额和无障碍说明由UI读取核心快照后动态投影。
- 改装增加的真实容量继续分页，不能拉伸底图、复制装饰人物或制造虚假载荷。绘制分区是表现锚点，经营容量仍由 `src/core` 决定。
- 客货型可按机身结构分上下舱或前后舱，但必须保持一个连续、可信的飞机剖面；不得为了排版另画第二套舱壁或地板。

## 原创与方向

- 统一头朝左；地图3D飞机继续按航迹方向旋转，不受本规则改变。
- 现实机型、博物馆或厂商资料只能用于通用结构研究，不下载或接入其图片、商标、涂装、注册号和线稿。
- 禁止文字、水印、棋盘格、黑底、外发光和背景；四角alpha必须为0。主体边缘保留抗锯齿，完全透明像素的RGB清零。

## 兼容与接入边界

现役13架v5资源仍由 `prepare-aircraft-art.mjs` 的历史 `sourceAtlas/nearBounds` 分支生成，直到逐架按本规则重画；该兼容路径不是新绘制模板。新资源配置必须显式提供独立 `cutaway` 与 `exterior` 文件，接入时UI应在两张完整图之间切换，并在外观模式下隐藏内部交互，不再创建或要求 `near` 蒙皮图。

这次仅交付一架样稿和规则，不把样稿加入 `src/core`、`public/art`、商店、机库、机场或PWA缓存。用户确认并指定接入机型后，才修改目录、UI切换和运行资源。

## 验收

- 自动检查两图均为1536×590、透明四角、非空主体、各只有一个显著连通飞机主体、左右留白、底部留白、可见宽度差不超过2像素、底部基线差不超过1像素、高度差不超过12像素。
- 人工检查同机型轮廓、视角、涂装、光照、朝向和容量分区；1客0货必须只见一个空客位且不见货舱。
- 接入运行时后再执行类型检查、核心单元测试、生产构建和Playwright，并覆盖桌面横屏、手机横屏、竖屏提示、外观/剖面切换、装卸、刷新、导入导出和离线启动。未接入的样稿不冒充上述流程已通过。
