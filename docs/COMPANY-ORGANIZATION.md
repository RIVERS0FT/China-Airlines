# 公司组织架构树 · 第一阶段（2026-09-14）

## 设计变更与边界

经营中心的“飞行团队”升级为“公司组织”。这是航空运输的人员成长层，不替换机场场景，不复制装货/制定路线页面，不引入通用经营后台或凭空客货。保留底部经营中心、顶部只读点券、左上任务、机队管理，以及装卸静默反馈。现有机场/机型/报价/成本/飞行时间/周转/离线8小时契约不变；本次未实施另行讨论的后台/离线统计改版。

首阶段仅飞行部和地勤部；没有物流员工、分公司、自定义多层团队、股权、内斗、随机离职或退休。人员是实际经营实体，飞机和机场只作为绑定资产显示。专业/管理数值为航空游戏化设计，不宣称真实航空组织规范或参考原作实测。

## 组织结构与唯一数据源

`career.employees` 是唯一人员名单，替代 `career.pilots`；不存在两份重复人员数据。员工保存ID、姓名、部门、岗位、飞机/机场绑定、专业/管理能力、潜力、特长、预付合同截止时间、入职模拟时刻、运输参与业绩、最近20条履历。

树为“玩家 → 两个部门经理位 → 已分配执行员工”，待分配人员单独展示。每部门最多8名执行员工和1名经理。没有经理时玩家兼管，所有原有基础经营仍可用。部门经理由部门和岗位唯一推导，不保存任意上级指针，因此不能出现重复上级、跨部门循环或无限层级加成。当前不实现多个团队。

每名执行飞行员只能绑定一架服役飞机，同机不能重复分配；每名地勤专员只能绑定一座已开放机场，同站不能重复分配。经理不能同时承担执行岗位。飞行员调离时必须停稳、结束周转、取消补能/后续计划并停止自动值勤；岗位失败由核心原子回滚。地勤调动不重算已开始的补能服务。关站前必须调离地勤。

公司2级、专业能力至少2、管理至少1、合同有效且未绑定资产时可任命经理，费用1,000金币＋2点券。任命替换已有经理时，原经理原合同/能力保留并转为待分配执行人员；全程原子提交。卸任免费，执行人员已满时需通过另一员工接任交换岗位。不能无限叠加经理头衔。

## 招募、成长与合同

飞行员最多8个执行岗位，招募1,800金币＋3券，续付600金币＋2券/7个营业日，原有技能训练400×下一等级金币＋3券。地勤招募1,200金币＋2券，续付400金币＋1券/7日，专业训练300×下一等级金币＋2券。经理沿用来源部门工资，不因临时升降职改变续约价格，不重复购买自动值勤权限。所有招募含7日工资；续约从 `max(simTime, paidUntil)` 延长604,800模拟秒。

新飞行员专业0、地勤专业1；管理1—3，潜力8—10（专业与管理培养上限）。招募仅在成功支付后推进存档内随机种子，读档、打开界面和失败操作不重抽属性。飞行员特长在“善于带教/稳健成长”中确定，地勤另有“高效作业”。管理培训为500×下一等级金币＋2券；稳健成长仅使管理培训金币九折，不改原有专业训练权益。善于带教在任经理时增强部门效果；高效作业仅使地勤补能提速额外2%。

合同到期不自动扣薪、不负债、不删员工。现有飞行员继续原规则：到期不启动新自动航班，已起飞航班正常抵达；已有专业技能经验计算保持原契约。新增经理和地勤效果只在任务开始且合同有效时应用；已锁定任务不因到期中断。预付工资按现有模拟营业日时间轴推进，未引入真实自然日欠薪。

## 经营效果与时间锁定

经理管理容量 `2 + 管理能力`。负载为本部门已绑定资产的执行人员数（待分配人员不占负载，合同到期但未解绑仍占位）。覆盖系数 `min(1, 容量 / max(1, 负载))`；超编只按比例降低新增管理效果，不限制原有飞机发航和补能。

### 飞行部

有有效合同的已分配飞行员、且飞行部经理合同有效时，新增公司经验比例为 `floor(min(2000, 管理×200 + 带教特长×200) × 覆盖系数)` 个基点，上限20%。在起飞时将飞行员ID、经理ID、管理能力、是否带教、当时负载写入 `career.flightStaffing[flightId]`。新增经验为 `floor((20 + 实际交付数量×5) × 基点 / 10000)`，由到达事件一次性发放；收入、点券、合金、基础经验公式均不替换。

只有有偿客货交付计入；空飞与自产物资不产生额外经验/员工运输业绩。新管理经验在起飞锁定，途中培养、换经理或合同到期不重算。员工参与航班/运输单位数在到达事件记入飞行员及当次经理档案，不重复结算、不增加运输收入。履历只记录招聘、分配、培训、任免与续约，运输使用累计计数而不每航班刷一条提示。

### 地勤部

没有有效驻站地勤时，新补能维持120秒。有效地勤时，提速基点为 `min(3000, 专业×200 + 高效特长×200 + floor((经理管理×100 + 经理带教特长×100) × 覆盖系数))`；无有效经理时经理部分为0。时长为 `ceil(120 × (10000-提速基点) / 10000)` 秒，最低84秒。

开始时只写入最终 `serviceUntil`；服务中换人、培训或续约都不修改该截止时间。费用仍0，完成前不补能，取消不补能；既有跨营业日恢复电力规则继续有效。机队能量页显示当前驻站配置对“新服务”的报价，正在进行的服务显示其锁定倒计时。

## 存档兼容与校验

包版本0.8.0、游戏存档8，IndexedDB结构仍1，依赖及锁定版本不变。v1—v6仍先用冻结校验迁移；v7使用独立的 `save-v7.ts`、`types-v7.ts`、经营/设施校验和目录快照，不随新版人员字段扩展。

v7飞行员原ID、姓名、技能、飞机绑定和合同保持。新增管理1、潜力10、稳健成长；入职时间设null并明确“旧版未记录”，运输计数从0开始，不伪造过往经历。资金、订单、飞机、在途票价/费用/到达时刻/能量不变，不收迁移费，不重发工资或能量。旧在途航班的 `flightStaffing` 对应键为null，不赠送新增经理经验；新派航班才写完整快照，到达后删除。

当前存档严格检查员工/履历/快照字段集合、数值范围、岗位限额、唯一ID（含生产ID）、唯一经理和资产绑定、开放机场、飞机调度权限、有效引用。快照键必须恰好对应在途航班，历史null受显式支持。非法存档、未知上级指针或循环式扩展字段拒绝，数据库不覆盖有效进度并保留原备份。视图折叠、选中员工和组织图缩放不写经营存档。

## 界面与验收

节点只显示头像/姓名、岗位、资产或管理容量、一个状态；待续约使用“!”与文字，不只靠颜色。点击节点在侧边查看能力、合同、训练、任免、续约与履历，支持跳转负责飞机/机场。树图拖动空白平移，鼠标/触控/键盘滚动可浏览，缩放70%—140%，部门可折叠。沿用 `GameViewport` 逻辑像素与75%—150%全局缩放，不另做按物理屏幕大小判断的布局。复用本地飞行员头像，地勤用姓名徽标；不宣称本轮已补齐独立人物原画。

必须验证：8+1岗位边界、命令原子性、重复飞机/机场与经理、任命/替换/卸任、专业/管理上限、工资到期、既有调度权限、在途加成锁定、实际有偿交付计数、地勤补能/取消/调动、关站限制、v1—v7迁移与损坏拒绝。浏览器在1440×900、844×390、667×375验证招聘/任命/分配、缩放折叠、跳转、导出刷新恢复、离线启动及非法导入；保留既有比例/竖屏提示与全部机场/航线验收。真实手机触控仍需设备验收，浏览器模拟不能替代。
