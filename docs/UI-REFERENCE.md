# v0.4 界面修订 场景界面对照与验收

本轮承接《中华铁路》的大载具、下方客货队列、地图选路与固定主要操作入口，将其转换为航空场景。路线交互现按参考操作修订：不再用“单段/多段”切换，也不再设置付费开通航线。原PR #4对应既有基线；新迭代仍通过功能分支独立验收，不把分支通过当作已合并或上线。

## 装载页

保留顶部资源、机场牌、大飞机、两侧换机、下方客货和右下角起飞入口。客货区用连续候运地面、不同旅客组/行李和货运车表达候运；标签仍然是真正的原生按钮，不能仅展示插图代替装载。

队列左右按钮每次滚动约一屏、保留一项上下文。支持触摸横向滚动和聚焦列表后的左右/Home/End；只有列表自身获得键盘焦点才处理这些按键，不拦截卡片或选择器操作。列表无溢出时禁用翻页。切换飞机、机场、客货分类或机上/候运区时回到队列开头；模拟时间推进和单次装载不主动重置滚动。

卡片显示最终目的地、人数/吨位、锁定报酬与装卸状态。飞行、周转、自动值勤、剩余计划、类型不兼容、客舱/货舱不足、候运区满必须明确说明，禁止显示“点击卸下”但实际不可卸。界面解释只读，核心仍然重新验证每条命令。

短横屏使用同一机体的紧凑侧视：缩短垂尾并去除SVG上下留白，不把整架飞机等比缩成小图标；保留翼面、起落架、舱位和清单入口。桌面继续完整侧视，不改变机型或经营数据。

桌面候运区保持完整竖向卡；844×390与667×375采用人物在左、数量/报酬在右的紧凑卡，关键操作/禁止说明至少11px，不以隐藏文字换取高度。引导期间检查状态文字完整位于卡片内。保持竖屏提示，不依赖锁屏。

## 航网页

地图只有一种路线编辑状态。飞机当前机场是隐含起点；玩家第一次点击已解锁城市形成第1段，继续点击其他已解锁城市依次形成后续航段。最多5段。经过其他城市后可以再次点击起点或之前访问过的城市；连续点击当前末端不重复添加。路线顺序直接由城市点击顺序决定，不显示“单段派航”“多段计划”或“添加某城市航段”模式按钮。

实线表示满足机型、机场等级和航程条件，虚线表示该段不可飞；方向箭头、起点0和访问序号说明顺序。返回同一机场时合并显示访问序号，不隐藏后续访问。已解锁城市满足飞行条件即可直接前往，不再出现“须先开通航线”“航线建设费”或用于放行的“已开通”状态。

预览调用核心legQuote读取当前航程及机场规则，不复制新的一套飞行公式。每次点击城市、撤销末段或清空路线实时更新图形；预览不能扣费、写历史routes、派航或改存档。飞行中不展示可执行的地面草稿。自动值勤中手动派航按钮禁用并说明须先停止值勤。

下拉城市选择保留为键盘/降级输入，并与地图点击使用同一“按顺序追加”逻辑。未解锁城市可以被查看并解锁；解锁成功后即可直接加入路线。自动往返仅在草稿恰好一个目的城市时可选，多段路线不显示成循环自动路线。

地图保留费用明细、可访问路线文字和WebGL降级入口。`routes` 只表示已经实际运营或自动值勤使用过的通航关系，可用于背景网络线，不是购买后才能飞的基础设施。所有绘制仅为读快照；与飞机真实位置或收益结算无关。城市字号/相机仍遵循MAP-LAYOUT.md。
