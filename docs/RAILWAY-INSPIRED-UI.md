# 中华铁路参考界面的机场经营页视觉层级

本文件是 `docs/DESIGN.md` 的界面补充。当前经营、存档、能量、客货、路线与派航规则仍以主设计及核心代码为准；本文件只定义机场经营页如何参考用户提供的《中华铁路》截图优化信息层级与操作强调。

## 参考边界

只借鉴场景式经营界面的布局关系：顶部资源计数器、中央载具主场景、机场/载具状态浮层、下部候运客货区、底部功能坞和高优先级发航入口。不得复制参考游戏的角色、列车、美术、图标、商标、任务文案、音效、付费货币或代码。中华航空继续使用仓库内原创机场背景、飞机矢量、旅客/货物矢量和既有中文文案。

本轮是 UI 投影与样式调整，不新增资源类型、充值入口、活动入口、聊天、任务、排行榜、商城货币等参考截图中存在但本作尚未设计的功能。所有按钮继续调用现有命令，不能用装饰性控件暗示尚不存在的业务能力。

## 机场页层级

顶部保留运营资金、机队、完成航班、帮助和存档入口。资金/机队/航班只改变为“图标徽章 + 深色计数器”的游戏化外观，不新增无效的加号按钮；显示值仍来自当前真实状态。

机场信息不再额外占用一整行主场景高度，而以站牌式浮层覆盖在机场背景上方。浮层保留当前机场、飞机状态、旅客容量、货物容量与能量等真实数据。非交互状态卡不得拦截其下方的飞机、返回所选飞机或其他既有操作；只有真实按钮接收指针事件。

飞机继续是机场页最大的视觉主体。机场背景、停机坪和候运区通过原创安全线、站牌和地面层次形成连续场景，但不能因装饰压缩飞机到不可辨认，或挡住左右换机、查看机上客货等入口。

## 客货与发航

候机大厅和机上客货仍显示 `GameState.orders` 中的真实订单，兼容主设计当前“一张新卡 = 1 位旅客或 1 吨货物”的规则以及旧存档历史聚合订单。视觉上弱化管理后台卡片感，强化目的地牌、人物/货物主体、数量和奖励，使订单更像停机坪上的待运对象；装载、卸载、分类、同目的地装载、左右翻页和键盘 Home/End 语义全部保持。

底部保留机场装载、航线地图、机场目录、机队管理、飞机商店、运营任务六个既有入口。`选择航线起飞` 仍只进入既有发航规划，但视觉上从底部功能坞抬升为右侧场景级主按钮。主按钮必须为客货翻页箭头和订单列表预留独立命中区域，不能通过 z-index 覆盖既有控件。

航线规划页继续遵守 `docs/ROUTE-DISPATCH-REFERENCE.md` 的独立精简布局，不继承本文件的机场页资源计数器、站牌浮层或底部装饰规则。

## 响应式与验收

桌面 1440×900、横屏 844×390、横屏 667×375 都必须同时保持主场景、客货区、底部功能坞和发航入口可达；主要操作命中区域不小于 44×44。窄横屏允许缩短辅助文字、缩小视觉间距和隐藏非核心副标题，但不得隐藏运营资金、机队、完成航班、机场、飞机容量/能量、候运订单或发航入口等核心状态。

页面不得产生横向溢出。机场浮层不得拦截 `返回所选飞机`；右侧发航按钮不得拦截 `下一组客货`；客货列表仍应支持鼠标/触摸翻页和键盘 Home/End。新增 Playwright 截图回归覆盖 1440×900、844×390、667×375，并继续运行既有机场浏览、客货滚动、装载、派航、地图、存档和离线回归。
