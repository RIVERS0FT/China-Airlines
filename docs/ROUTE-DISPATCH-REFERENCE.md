# 航线选择与起飞界面参考布局

本文件补充 `DESIGN.md` 与 `MAP-LAYOUT.md`，只调整航线地图的呈现与操作编排，不改变 `src/core` 的路线、能量、订单、机场解锁或结算规则。

## 参考边界

本轮参考《中华铁路》“选择路线/发车”画面的信息层级和操作习惯：顶部集中显示目的地、行驶/飞行时间、净利润和成本；地图占据主体；地图内保留当前载具、可达范围、城市节点和路线草稿；底部集中放置地图缩放、路线后退、路线撤销、取消起飞和确认起飞等高频操作。

只复刻布局关系、信息密度和交互节奏。不得复制参考游戏的地图、车辆、按钮贴图、字体、图标、商标、音效或截图内容。中华航空继续使用原创矢量地形、原创飞机图形和现有航空化城市/机场数据；地图仍是游戏化示意图，不是导航或行政边界资料。

## 桌面与横屏结构

1. 顶部“发车读数条”改为深色仪表外观，固定展示目的地、预计时间、运输净收益和运营成本。交付收入作为次级信息保留，不取代净收益。
2. 地图主体采用明亮游戏地图风格：绿色陆地、蓝色水域、河流、道路、山脉和树林均由 PixiJS 原创矢量绘制。机场节点显示城市名及简短机场状态。已解锁、未解锁、当前选择保持可区分。
3. 当前所选飞机在地面时也应在地图显示，并显示游戏化航程范围圈。范围圈只用于经营提示，不作为真实地理覆盖说明。飞行中的飞机仍按锁定航段动画显示。
4. 草稿航线使用高对比黄色主线和方向标记；失败航段保留错误样式。路线草稿只读预览，不扣费、不结算。
5. 地图放大、缩小、重置固定在地图左下角并保持触摸尺寸。右侧保留竖排“原创示意航网 / 非导航地图”提示。
6. 路线编辑按钮不再放在地图下方独立控制条。它们直接覆盖在地图底部：缩放按钮之后依次放“路线后退”“路线撤销”“取消起飞”，最终“确认起飞”独立靠地图右下角，形成与参考画面一致的“左侧连续编辑、右侧最终动作”布局。按钮不得遮住地图缩放，也不得与底部主导航重复出现第二个起飞按钮。
7. 原生城市下拉、“城市详情”、自动往返和“逐段费用与交付”保留为地图左上角的小型浮动工具条，不再占用地图下方一整行。展开费用明细时使用受限浮层，不得把短横屏地图向上挤压。
8. 地图主体应因此获得原控制台占用的垂直空间；路线操作属于 UI 草稿，仍不得改变核心结算规则或提前写入经营状态。

## 短横屏与可访问性

844×390 和 667×375 下，顶部读数条压缩字号和间距，次级路线文字可隐藏；城市选择、地图缩放、路线编辑与确认起飞必须仍可操作。地图视口高度不得低于 90 像素；本布局目标是让地图占可用工作区的大部分高度，而不是把路线按钮挤到地图之外。

所有图形按钮必须保留明确的 `aria-label`，既有测试用 `data-testid` 不因视觉改版而失效。原生城市选择仍是 WebGL 失败、触摸误操作和辅助技术用户的完整替代入口。

## 回归验证

浏览器测试至少覆盖 1440×900 与 844×390：进入航线地图后能看到四项顶部读数、地图缩放控件、城市选择和路线按钮；选择上海后目的地读数更新、草稿路径写入 `data-preview-path`。还必须校验缩放按钮位于地图左下、路线编辑按钮位于其右侧、最终确认起飞贴近地图右下，按钮整体处于地图边界内；地图下方不得再出现路线专用控制条或重复的“选择航线起飞”主按钮。路线后退与清空不修改核心状态；确认起飞继续复用现有 `dispatch` / `dispatch-plan` 命令。保存截图用于人工检查横向溢出、按钮遮挡和短横屏地图高度。
