# 飞机原图剖面直排与统一配准（2026-09-16）

本增量替代 `DESIGN.md`、`AIRCRAFT-CABIN.md` 中重复裁取舱壁、另绘地板、叠加舱壁边框以及机身随容器分别拉伸的美术约定。只调整展示，不改机型、实际容量、装卸规则、存档9、数据库1或经营结算。

## 当前绘制结构

原机型剖面 PNG 是唯一舱室底图。客货内容层完全透明，只放置无扶手座椅、托盘、真实订单人物/货物和原有标签；不再生成另一张内部图、裁取原图重新铺墙、绘制 SVG 地板或覆盖切口边框。空的 `cabin-room-floor` 仅是非交互、不可见的几何参考范围，用于现有接触点测试，不包含任何背景、美术或子视图。

层次固定为：原剖面机身 → 透明家具/订单交互 → 近侧外壳。客货型仍为上客下货，56%/44%；纯客/纯货仍为单舱。继续使用现役13机型既有 `interior` 标定，不伪造新容量或改变有限锚点分页。乘客臀部/坐垫、脚底/椅脚以及货物/托盘的二维接触点计算保持。

`aircraft-projection.ts` 将原画布和已配准近侧外壳的完整包围范围一起适配场景，只计算一次等比缩放、居中和底部位置。`CutawayCabin` 中机身、舱位及近侧外壳都置于同一个 `aircraft-art-canvas`。源坐标只在这一个父容器中映射；图片解除通用 `max-width`/`max-height` 限制，不再各自执行第二次裁切、contain、镜像或布局拉伸。近侧超出原1536×590画布的机翼/发动机也纳入适配范围。

显示或隐藏外壳不改变适配范围，不重建机舱、不重置分页、不改订单。外观模式继续使用 `inert` 和 `aria-hidden` 屏蔽机内操作；查看机上客货后恢复剖视和键盘焦点。ResizeObserver 读取逻辑 client 尺寸，避免把 UI 缩放后的屏幕尺寸二次施加到模型；尺寸不变时不重复更新状态。

## 主操作位置

普通导航七个固定槽位继续左对齐、保持跨页面位置不变。机场“制定航线/制定路线”主按钮以独立自动左外边距贴靠导航栏右侧内边距。规划页“检票起飞”固定在地图右下内边距，路线后退、撤销、取消和查看路线仍在左侧。地图空白区域和提示层保持触控穿透，按钮本身可交互。

## 后续飞机绘制与导出流程

1. 先确定一个机型的完整母版，锁定左向、画布、透视、机头、尾翼、舷窗基线、机翼根部与发动机中心。复制同一母版，以蒙版移除近侧蒙皮得到剖面；不要分别生成两架外形相近的飞机再凭目测拼合。
2. 剖面保留已画好的舱壁、地板和切口，不把座位、人物或订单烘焙进去。家具和客货锚点直接标在这张原图上。
3. 新一代分层源图应保留同尺寸透明画布、同原点，不分别自动裁边或缩放。当前 v4 是1536×1024历史图集，上590像素为剖面，下434像素为近侧图层；在未重新导出资源前必须保留各机型 `nearBounds`，不能把历史图层强行改成全画布位置假装已经对齐。
4. `extract-aircraft-layers.ps1` 检查输入尺寸、矩形范围及外壳对舱室的实际透明度覆盖，再按同一配准记录导出运行资源。静态外观合成显式使用像素坐标，避免 PNG DPI 引入隐式变换；同时输出50%透明叠合 SVG 供轮廓复核。生成器不能仅凭“舱室被盖住”证明所有轮廓一致，仍需人工检查机头、尾部、舷窗、翼根和发动机连接。
5. 在100%、缩小及放大状态逐一审阅剖面、外壳、半透明叠合图。出现结构差异须回到同一母版局部修改，不新增页面 CSS 偏移掩盖。改变源图格式时同步更新配准、PNG尺寸测试、外观合成及离线资源版本。

## 验证与交付边界

新增几何单元测试覆盖13机型、宽/窄/高视口、成倍缩放、源图尺寸和无效输入；浏览器回归增加原底图仅一次绘制、内容层透明、等比配准、外壳过界、缩放与切换不漂移，以及两个主操作右对齐。原装卸、分页、真实身份、外壳覆盖、焦点、跨页面导航、手机横屏和75%–150%缩放回归保留。

本次不重新生成或重绘现役13机型的 PNG。统一坐标修复的是重复绘制与布局变形，不能自动消除历史两张源图本身已经存在的结构差异。导出脚本属于后续制图工具，不作为运行时依赖，也不在每次部署时重新生成美术。
