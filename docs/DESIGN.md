# 中华航空 · 当前设计

## 产品与架构

本项目是航空版《中华铁路》式单机经营游戏：保留场景装载、真实客货、顺序选路、载具成长和到达结算的操作习惯，使用原创素材，不复制参考游戏的商标、图片、音效或代码。未取得原作证据的数值均明确作为航空化适配，不宣称完整一比一复刻。

`src/core` 是经营状态的唯一写入者，不依赖 DOM、React、PixiJS 或数据库。UI 只发送命令；机场、地图和飞机场景只读状态快照。到达、周转、补能、生产和离线推进都由时间事件结算，不使用动画回调，不允许重复结算。

## 新公司与首航教程

新局拥有北京1级基地、18,000金币、24点券和空机队，不再赠送初航机。上海需支付4,000金币解锁。空机队仅在尚未拥有过飞机的合法开局阶段有效；购机或组装后不得通过篡改存档清空所有飞机。

教程默认开启，运营教练林岚以原创半身像、宽对话框和可点击蒙版，引导玩家购买上海机场→选择1格钻石DA40（2,300金币）→免费配置1客位或1货位→装载真实订单→选上海并确认起飞→按时间抵达→领取首航奖励→完成培训。蒙版为当前真实按钮或弹窗留出可操作区域；机场详情仅为解锁按钮开孔，其他详情内容仍处于蒙版下；点击暗区只定位操作，不自动消费或推进经营。对话框只显示人物、当前经营步骤和右上角的“跳过引导”，不再放置存档设置、行动按钮或通用点击提示；全局顶部栏仍可操作。首步高亮未开放筛选和上海机场卡片，不高亮已选中的无效导航；暗区点击定位真实控件并显示高亮反馈，在购机弹窗中只聚焦输入，不代替确认。首航地图高亮上海点，视角和缩放变化时使用同一球面投影重新测量蒙版；暗区定位仅调整相机，顶栏只读，选点后再高亮检票起飞。首航培训结束后点击暗区结束教程。帮助中可重新开启；步骤由已提交的经营状态推导，刷新和取消购机不会跳步或额外发奖。购机弹窗关闭后丢弃未确认选配。半身像位于对话框左侧内部，允许头肩超出框顶；对话框桌面最大1040px，手机横屏保留左右边距。教程使用物理视口顶层弹出框，避免套用游戏逻辑画布的缩放与容器查询；窗口尺寸、滚动、图片加载及弹窗切换都会重新测量高亮区域。离线回报、设置与竖屏提示优先于教程。

新公司的首航购置后余额11,700；北京至上海DA40满载单程成本96、收入326、运营净利230，领取首航1,500奖励后余额13,430。所有金额通过真实经营流程验证，不凭教程弹窗结算。

教程中从机场列表或暗区定位进入机场详情，解锁首座目的地成功后都关闭详情并进入飞机商店，高亮真实购机按钮；此页面跳转不额外扣款或交付飞机，避免购机步骤被旧详情弹窗遮住。

## 运输经济

球面两机场的大圆距离为 `km`，航空版距离单位为：

```text
D(a, b) = floor(km(a, b) / 4)
```

普通旅客和货物订单的基础收入为：

```text
订单基础收入 = 数量 × (D(始发地, 最终目的地) + 50)
```

服务类型只决定订单表现和专业货舱条件，不改变金币倍率。自有生产物资运费为 0。

设编队等级为 `G`（0–6），进化等级为 `L`（0–20）：

```text
编队收益倍率 = 1 + 0.20 × G
进化收益倍率 = 1 + 0.015 × L
收入 = floor(该站交付订单基础收入总和 × 编队收益倍率 × 进化收益倍率)
```

没有满载奖励，也不检测是否满载。装载更多真实订单才增加基础收入。满级编队和进化合计为基础收入的 2.86 倍，避免原有 64 倍编队收益使后期价格失效。这些倍率与下述成本是航空版平衡参数，不是原作核验公式。

设实际航段距离单位之和为 `D路线`，强化后的重量、速度为 `W`、`S`，机型额定总容量为 `C`（不取已分配或已装载格数），航段数为 `K`：

```text
路线运行成本 = floor((D路线 × (0.24 × C + W × S / 600000)
                       + 12 × C × K) × (1 + 0.12 × G))
```

成本由随航程发生的运营支出和每次起飞的地面处理费组成。空机、未分配舱位的飞机仍按额定机体计成本；拆掉舱位不能规避成本。每多停一站增加该站处理费。整数系数计算后只取整一次；多段计划按累计成本差分分摊，航段扣款之和严格等于整条计划成本。订单收入始终按始发地到最终目的地计算，绕行不能增加收入。

平衡目标为基础机型普通满载航班约 65%–75% 利润率（短航线的固定票价部分会略抬高比例），低装载率与空飞可能亏损。此比例不计购机、机场、员工和改装投资，也不承诺随机候运池总能满载。完整价格、成长成本和测算边界见 [BALANCE.md](BALANCE.md)。

```text
净利润 = 各站实际交付收入之和 - 路线运行成本
```

净利润允许为负。报价是只读投影，只有成功起飞才扣除该航段成本；抵达只结算已锁定的交付收入。

## 客货、航班与离线事件

- 新订单代表 1 位旅客或 1 单位货物，具有固定始发地、最终目的地、位置和基础奖励。
- 装卸移动同一个订单对象，不复制订单。中转不付款；最终交付后删除订单并只记录一次统计。
- 已接受订单仍以不过期状态保留；在始发机场装载后卸回只恢复待装载，不标为中转。只有订单实际位于始发地以外的机场候运区时才显示中转；中转标签使用不透明浅金底、深色无描边文字，可用和不可用时均保持清晰，不随人物灰化。
- 自然客源补充每 120 秒检查所有开放客流的机场，未接受订单在生成 360 秒后过期；手动刷新只替换并补充所选机场的未接受订单，不补齐其他机场、不重置自然补充时间，已装机、已接受和中转订单保留。每日每机场前 10 次免费、之后每次 1 点券、最多 30 次的规则不变。
- 最多规划 12 段。计划保存路线总成本契约，后续航段按同一契约结算。
- 飞行起点与终点、出发和到达时间、成本、收入及载荷在起飞时锁定。
- 离线推进上限 8 小时；墙钟回拨不倒退模拟时间。主动导入只恢复模拟状态，不根据文件年龄发放离线收益。

## 公司组织与总经理

`career.employees` 是唯一员工名单。运输与总部组织包含 1 个总经理 NPC 槽位、飞行部与地勤部各 1 个经理槽位、最多 8 名飞行员和 4 名地勤专员，运输与总部岗位合计最多 15 人，业务团队岗位另计。总经理使用公司岗位 `department: company`、`role: manager`；公司没有专员岗位。总经理和部门经理都不是基础手动经营的前提。

总经理从人才市场招募，录用即任命：费用为 2,400 金币加 4 点券，包含 7 天合同，初始专业 2 级、管理 1 级、潜力 6–10；续付 7 天为 800 金币加 2 点券，培训和合同沿用现有人员规则。本期不支持通过内部晋升、降职或跨部门转任产生总经理。人才市场替代原“招募”入口，显示距下次整批更新的倒计时；候选包含总经理、两部门经理、飞行员和地勤专员五组，每组 3 人，共 15 人。

人才市场直接按五个岗位分组展示全部15名候选，不提供“招募岗位”下拉框。组标题显示岗位和已聘人数/岗位上限；每张人物卡包含姓名、头像、岗位、潜力、特长、含7天合同的招募费用、每7天续约薪资及独立招募按钮，并注明不自动续约。卡片本身不设选中态，也不以整卡点击录用；岗位已满或资金不足时，原因和禁用按钮均显示在对应卡片内。删除全局底部招募区，组织树职位空槽进入人才市场后定位相应岗位组。这些布局调整不改变30分钟更新周期、录用费用、续约或存档规则。

所有招募入口均为录用即上岗，不再新增待分配人员：飞行员按机队顺序分配到首架未绑定员工且允许调岗的飞机（未飞行、无自动值勤与后续航段、未补能且地面周转已结束），同时开启该飞机的飞行员标记；地勤按已开放机场顺序分配到首座未绑定地勤的机场；经理直接占用对应唯一岗位。岗位人数已满、没有可用飞机或机场时，界面禁用招募并显示原因，核心也在扣款和生成员工前拒绝；过期合同仍占据原岗位。人物卡显示招募后的自动分配目标，点击时由核心重新检查，录用、扣费、资产分配与候选补位原子完成。新专员有本部门经理时自动直属该经理，否则由玩家直管；招募新专员不改变已有员工的分配和汇报关系，仍可手动调整；总经理任命时自动接管部门经理的既有规则保留。原存档中的未分配员工不自动迁移，存档格式为15。

人才市场每30分钟（1800秒）自动更新全部15名候选，由核心模拟时间事件驱动，以全局经营时间的整半小时为边界，正常在线按真实时间1:1推进。候选在周期内固定，成功录用后仍只补位该名候选、不重置整批倒计时；打开面板、刷新网页和切换语言不额外重抽。离线推进经过每个刷新边界时同样整批更新，沿用8小时补算上限与墙钟回拨不倒退规则，渐进推进和一次离线推进得到相同结果。更新使用独立候选随机种子和新编号，不修改已雇佣员工；刷新后提交旧候选编号必须拒绝且不扣费，已发生的时间推进和定期更新继续保留。刷新时刻从现有模拟时间推导，不新增存档字段，格式为 `version: 15`；已有当前格式存档的候选保留到下一个整半小时边界。

总经理无员工上级，不绑定飞机或机场；业务团队主管也可直属总经理，其产出规则见公司业务文档。部门经理可向总经理或玩家汇报；专员仍只能向本部门经理或玩家汇报。招募总经理时，现有部门经理自动成为其直属下属；之后新聘或内部晋升的部门经理同样自动直属总经理，玩家可再调整汇报关系。总经理除真实组织层级外，为直属业务团队增加管理效率；不增加航班收益、跨部门培训折扣或补能加成；既有部门经理对本部门专员的效果不变。组织树顶部显示真实总经理档案或可点击的招募空槽，不再将玩家画作总经理 NPC。相关规则见 [COMPANY-ORGANIZATION.md](COMPANY-ORGANIZATION.md) 与 [COMPANY-TALENT.md](COMPANY-TALENT.md)。

公司组织页移除“公司事务”和“公司纪事”入口及面板、员工头像上的事务提示标记；任务中心同步移除公司事务折叠区。人才市场招募、组织树、员工任职/培养/履历和机队负责飞行员跳转保留。事务与纪事的删除只涉及对应界面，核心记录规则和 `talent.deferred`、`talent.milestones` 存档字段及严格校验继续保留；当前存档仍为 `version: 15`，不因界面删除使有效进度失效。

## 存档与持久化

当前且唯一支持的保存格式为 `version: 15`，IndexedDB 结构版本为 1，两者独立管理。导入只接受字段集合、枚举、数值范围、引用关系、订单、人员、航班、能量、客货容量分配和路线成本契约全部有效的当前存档。旧 `version: 13` 及所有其他版本文件拒绝导入；本版不提供自动迁移。升级前可导出旧版存档供旧版恢复，但新版本无法读取它；已有进度在本版会进入恢复界面。

版本不符、未知机型、未知机场、额外或缺失字段、非法数字及引用不一致都会拒绝。失败导入不得替换主存档或备份。保存时在同一事务中轮换上一份有效主存档到备份，并使用 revision 防止多标签页陈旧写入。

仓库不保留旧格式迁移代码、冻结目录、历史测试夹具或旧版设计规范。格式改变时直接更新当前设计、验证器和测试；不自动猜测或改写不兼容文件。

## 视图与资源边界

- 商店有游戏总容量 1 至 10 格各一架机型，不再按客运、货运、客货型出售。商店购买必须先完成免费客货选配，再确认购买和交付；至少分配一格，客位与货位之和不得超过机型总容量。选配只包含本次购买的舱位配置，不赠送后续免费改装次数。确认前关闭、取消或刷新不会扣款或交付；核心在同一命令中校验选配、扣除机价并交付配置好的飞机。零件组装机仍为空机身，需在机队管理中付费分配。可留下空格；更改配置时已装客货不得超出新分配容量。飞行、补能、自动值勤与地面周转期间不能改装。新增总格数每格收费 120 金币，新增客位每格另收 80、货位每格另收 100；减少容量不退款。专用货舱需要先分配至少一格货位，拆除最后一格货位前要先拆除专用货舱。原有扩舱升级停用，保留零级字段作严格存档结构的一部分。

- 机队管理将飞机与航班合为一页：按“找飞机 → 查看当前任务 → 执行管理操作”组织。紧凑列表只显示身份、运行状态、位置/航段、剩余时间、载荷和能量；按全部、待命、在飞、补能快速筛选，其他状态用选择框筛选。所选飞机区集中呈现航段进度及锁定收支、机场入口、补能、客货分配、性能改装、人员与出售操作；航班金额不在列表重复铺开。提供补能、客货改装、性能改装及自动值勤的快捷定位按钮，定位时移动键盘焦点但不执行经营命令。筛选隐藏所选飞机时保留操作对象并明确提示，可清除筛选。移除原有双页签、重复机库飞机列表与“机上清单”折叠区。顶部概览和底部导航都进入同一页面；筛选、搜索与所选飞机在本次会话的页面切换间保留。列表提供详情定位和返回入口，窄屏上下排列；查看、搜索和切换不修改经营状态。
- 页面共用全局骨架和底部一级导航；所有一级页面删除页面标题栏，直接显示操作工具与内容，页面名称通过主区域的无障碍标签及导航选中态识别。公司组织保留员工统计与人才市场操作，地图和机场保留场景运行信息。一级页面不提供关闭按钮或 Esc 返回，使用底部导航按钮切换。任务、设置、帮助和详情使用带标题、可关闭的临时浮层。
- 飞机商店卡片左上角显示机型名称，移除重复名称、购机选配免费及客货布局两项说明。购买按钮直接显示“支付 {金额} 购买”；不可用原因显示在按钮旁。交付机场选择移入购机选配弹窗，默认沿用当前机场或本次会话的选择；改变机场不清空已填客货数量。商店按是否拥有任一符合等级的机场判断能否进入选配，确认时再校验实际所选机场，避免低等级默认机场阻挡其他可用机场购机。确认按钮同样显示实际机价，选配、资金、机位及等级检查通过后才允许购买；取消与刷新不产生交易。
- 导航按钮以金色选中态为高度基准：正面使用铺满高度的两色渐变，普通、悬浮、选中与禁用状态统一3逻辑像素内底边与2逻辑像素外底边，使正面和底座等高，不通过加深正面底部的大段渐变制造额外厚边。按钮采用伪3D按压反馈：按下时底部侧边和外阴影消失，仅保留顶部内凹阴影；松开恢复当前普通或选中外观，点击范围与布局位置始终不变。
- 所有按钮统一普通、悬浮、选中与按下外观：普通蓝白底，悬浮提亮，真实选中/展开状态以金色强调，按下采用内凹反馈；禁用按钮不响应悬浮或按下，键盘焦点有独立清晰轮廓。导航、页签、筛选、语言/缩放、员工与飞机选择沿用已有状态；购买、领奖、关闭和起飞等即时动作不产生虚假的持续选中状态。客货、肖像和其他图形按钮保留原有轮廓与尺寸，通过描边或光晕反馈，避免按钮状态变化挤动页面。

## 验收与交付

单项修改只运行受影响的定向测试，不运行全量套件；规则变化需更新相关设计和测试，生产代码变化需完成类型检查、对应路径构建及相关浏览器验证。推送时进行完整测试：类型检查、全部核心/持久化/资源测试、根路径与 `/china-airlines/` 子路径生产构建，以及全量 Playwright 流程。完整浏览器流程覆盖桌面横屏、两种手机横屏、竖屏提示、刷新恢复、导入导出、离线启动和关键经营链路。

测试按单元功能、跨模块经营/持久化、完整游戏流程和浏览器专项回归分层，目录与入口见 [TESTING.md](TESTING.md)。玩法验收必须验证操作后的金额、订单、状态和持久化结果；禁止用源码单词或界面文案命中代替功能测试。完整新开局流程不使用已配置飞机或注入资金的夹具。

生产地址为 `https://riversoft.top/china-airlines/`。本仓库私有 `main` 更新后，所有 CI、UI 契约与生产工作流任务统一使用 `[self-hosted, Linux, X64]`；生产工作流在自建 Runner 上重新执行类型、核心与持久化、子路径构建和完整浏览器验证，再由本仓库现有自建 Runner `VM-0-10-debian` 使用 production 环境中的专用 SSH 密钥上传带 SHA-256 校验的静态包。`game-hk` 不增加 Runner：其 `deploy` 账号的受限 SSH 命令只接受本游戏发布包，并由固定生产脚本写入 `/var/www/riversoft-games/releases/`，把主站预留的 `/var/www/riversoft/china-airlines` 原子切换为本次不可变版本的链接；公开文件哈希不符时恢复旧链接。RIVERSOFT 主站工作流保留该路径，不覆盖游戏，也不把主站部署成功视为游戏上线。发布前后均检查当前 `main`，旧候选不得覆盖新提交。游戏作为一方静态页面保留 IndexedDB 与 Service Worker，主站首页仍是网页广场。创作者发布令牌及其 10 MiB、opaque-origin 沙箱不承载本游戏。原 GitHub Pages 自动发布停止。

未运行或失败的检查必须明确记录。功能分支通过 PR squash 合并；日常修改使用仓库既有部署路径，不重复生成 ZIP。只有实际部署成功并验证目标端点后才能宣称上线。

## CI 证据只保留最近一次失败（2026-09-27）

成功验证不上传测试报告、截图、trace 或 JSON 构件，结果保留在工作流日志。仅验证失败时保存失败上下文与已有证据，命名包含 run ID、attempt 和分组。按每个仓库跨验证/生产及 UI 专项工作流保留最近一次失败 attempt 的全部分组证据；后续成功不覆盖该记录，下一次失败证据上传成功后才删除更早证据。若没有成功上传的新证据，保留上一份；若一直没有新失败，按配置在 90 天后自动到期。失败判定发生在发布包上传之前，不能因报告上传错误再次触发重复证据上传。

独立 artifact-retention 工作流在 CI/生产运行结束后串行清理，也允许手动触发。清理只执行默认分支受信任代码，使用 Actions write 权限按严格名称白名单和真实运行/attempt 状态处理，不下载或执行 PR 产物；分页读取所有构件，保留进行中/重新运行的任务与未知构件，不删除工作流或日志。历史成功报告及更早失败报告纳入同一规则。测试失败仍是失败，权限或清理失败要如实显示，不能改成验证成功。

生产发布包是验证与部署之间的临时交付物，继续保留校验及全部发布门槛；最多保存 1 天，完整生产运行成功后自动删除，失败或进行中不提前清理，以便恢复/重试。服务器既有备份、不可变版本及回滚保留策略不变。成功测试零报告与成功部署零残留发布包分别验收，不把源码合并等同于线上生效。
