# 中华航空 · 航空化复刻设计 v0.4

状态：随航调度员、机队更新与可恢复分步引导。沿用v0.3场景、真实订单、九种飞机、四类改装和五段计划。未被本设计替换的规则见 ARCHIVE-V0.3.md，地图可读性继续遵循 MAP-LAYOUT.md。

## 1. 目标与冲突处理

继续制作航空版《中华铁路》，不回退成经营仪表盘。顶部资源、机场大飞机、下方客货卡、两侧换机、底部操作与居中机库构成主要交互。使用原创航空素材，不复制参考游戏的素材或代码。

原作App Store开发者说明是“人员提供自动装载”的参照，网址：https://apps.apple.com/cn/app/中华铁路/id885305981 。此前设计已记录这一来源。本轮雇用价格、残值及教程步骤是明确的航空化规则，未声称原版完全相同；仍未固定原作所有版本或完成像素级复刻。

本轮明确替换v0.3“不售机”和“所有飞机免费自动往返”的规则。旧存档每架飞机保留原免费自动权限，不追收费、不重置已有在途运输；新购飞机须单独雇用调度员。

## 2. 不变架构

中文、横屏、2D、单机Web/PWA，无账号、业务后端、外部地图、在线字体、广告或遥测。TypeScript、Vite、React、PixiJS8、Zustand、Dexie/IndexedDB。只有src/core写经营状态；界面发送命令、读快照，动画不结算。

保留8小时事件式离线推进、时间回拨规则、订单最终目的地单次付款、独立容量与航程校验、事务主存档/备份和revision并发保护。save-v3.ts及catalog-v3.ts冻结旧版校验参数，仅用于迁移，不创建第二个现行模拟核心。v1/v2基线不改，不用新版参数给旧航班重新计价。

## 3. 随航调度员与自动值勤

每架飞机新增dispatcher:boolean，表示绑定这架飞机的一个调度席。没有独立角色交易、随机抽取、技能树或转岗。新局免费首架飞机配有培训调度员，新购买的飞机没有调度员。

一次雇用费12000游戏币，无周期工资和闲置扣费。已有调度员、资金不足、飞行中、周转中、自动往返或后续计划未结束时，禁止雇用/解聘。解聘保留机体、改装和全部订单，不退雇用费；再次雇用再次收费。

手动装卸、手动单段和有限多段计划不要求调度员，循环自动往返必须配备调度员。传统起飞自动选项仍要求已装载且订单全部直达。机库“启动自动值勤”允许从空舱开始：先检查当前位置、航程、两端等级、已开航线及机上订单全部直达，再按现有队列顺序装入放得下的真实订单。

有单支付正常运营费并起飞，无单则保留值勤航线，等待下一次120秒供给补充；不扣空飞费、不凭空创建订单。启动时有订单但无法支付首段费用，整个命令失败，装载和资金不部分改变。后续值勤资金不足沿用既有停止自动规则，保留已装订单和所在机场。停止值勤不取消已起飞航班；到达并周转前不能解聘。

## 4. 安全出售与历史机队任务

机库展示预计残值与禁止原因。出售需地面停靠、周转结束、无自动往返、无后续计划、机上零订单且出售后至少剩一架飞机。装有旅客或中转货物时必须先逐单卸空，卸载仍受机场候运上限限制。售机不得删除客货、自动卸至异地或突破等待区容量。

残值=floor(基础机体价格×0.5+实际改装投入合计×0.25)。改装投入逐级沿用原舍入价格，不退雇用费及机库扩建费。赠送机体有基础残值，但唯一飞机不能出售。机体与升级买入再卖出不能获利。

界面必须再次确认，取消不发送命令。确认后核心重新验证条件，移除机体、改装和绑定调度合同，资金增加并记录日志；机位占用释放而机库总容量不减。机场、航线、其他飞机和全部订单不变，nextId不回退、不复用，重复出售拒绝。所得不计运输收入、航班数或客货统计。

新增fleetPeak记录历史最高同时拥有飞机数，新局1，购买后取最大值。机队任务描述改成“机队曾达到3架飞机”；满足后即使售机，未领取资格和已领取记录都保留，奖励仍只领一次。校验fleet.length<=fleetPeak<=16，已领取机队任务须峰值达标，不能依赖仅60条的日志推算。

被选中飞机售出后机库及主场景回退到仍存在的飞机；地图组件以飞机ID为身份，不保留已售飞机的计划草稿。

## 5. 分步起航引导

tutorial取available/active/completed/skipped。新局available，只展示可开始的入口，不强制遮罩。所有尺寸可从“操作帮助→开始分步引导”进入；旧存档迁移为skipped，避免打断经营。

active时资源栏下显示引导条，为真正的客货卡或原生按钮加描边。步骤按实际状态派生：装载→进入地图→开通航线→确认起飞→观察到达→领取首航奖励→完成。定位只切屏、打开任务或聚焦控件，不代替点击、装货或派航；不加速、不暂停、不额外发钱、不清空进度。

刷新依据已保存的经营状态恢复，已在途航班不再次派遣。任务弹窗期间隐藏引导条，领取后关闭弹窗回到完成提示。只有首航任务已领取才能完成引导。随时可跳过；帮助可重新打开并定位到当前真实进度，不强制重做首航。高级/异常经营状态不保证由教程自动求解，教程不是代玩脚本。

短横屏压缩引导与装载区，保留客货、起飞、跳过操作。人员和售机区域位于可滚动机库弹窗，窄横屏单列，不遮挡主场景。

## 6. 存档格式与迁移

包版本0.4.0、保存格式4、IndexedDB结构版本仍为1。根字段新增fleetPeak/tutorial，飞机新增dispatcher。所有字段精确校验；dispatcher必须为布尔，自动路线须有dispatcher，completed须已领首航奖励，不允许指向售出飞机的孤立订单。

v1/v2经各自冻结校验和既有订单转换后补齐字段；v3先通过冻结v3校验。迁移设置fleetPeak为现有机队数，tutorial=skipped，每架旧飞机dispatcher=true。保留资金、机位、改装、航线、订单位置/ID/数量、序号、在途数值和时间锚点。不借假冒旧版本跳过严格字段检查，v4不再次迁移或重发权限。

正常启动保留墙钟差用于离线补算；主动导入/备份恢复重设墙钟，不领旧文件时间收入。JSON上限1MB，失败不覆盖有效进度。v4不能由旧游戏读取，升级前建议导出备份。
