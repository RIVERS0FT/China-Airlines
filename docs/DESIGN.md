# 中华航空 · v0.5 基础能量预算

本轮从界面补齐转向实际运营约束：按已读取的2016年攻略记录“飞行每分钟消耗1点”的比例，新增能量预留、不足停止与地勤补能。并未完成原作全部数值复刻。

## 设计冲突与继承

旧版只检查运营资金、航程和机场等级，可以在有供给时一直自动飞行。本轮明确替换这一无限连续运行规则；除 [ENERGY.md](ENERGY.md) 的能量条款外，完整沿用 [ARCHIVE-V0.4-ROUTES.md](ARCHIVE-V0.4-ROUTES.md) 及其引用的人员、机场浏览、航班运行和经济规则。不能把界面禁用当作核心已实施限制。

默认240点容量取自旧攻略的一个示例，并非确认所有原版车型都是240点。120秒免费地勤补满、按整数秒预留和取消规则是航空化暂定设计；没有查明原版恢复时点、费用及不足一分钟的舍入，必须在界面和数值档案中明确，不擅称等价。暂不添加未经核实的原版付费货币。

## 运行与兼容

包版本0.5.0，存档格式5，IndexedDB结构仍1；依赖版本不变，lockfile只更新根包版本。每架飞机有独立可用能量、当前航段预留量和补能截止时刻。唯一写入者仍为src/core；UI只显示数据并发送命令，不用动画或计时器回调扣能。

手动、自动、多段全部经过同一depart入口检查并预留。余额不足时当段不能起飞或扣钱；已有在途航班正常抵达。后续计划或自动值勤遇到不足，在实际机场停止，保留已装载订单。补能需完成周转、停止值勤和取消后续计划；完成前不增加能量，取消也不补。补能不是飞行，不产生运输收入、不消耗或清空客货。

冻结v4校验器和catalog-v4。旧版v1—v4先严格验证再迁移到5；旧资金、订单、改装、时刻和已锁定航班不重算，每架旧机赋满初始预算，当前旧航班豁免追扣。只有今后起飞才预留。v5读档不能重复赠能，非法或缺少字段拒绝且不覆盖有效进度。

## 验收与交付

验证整秒耗能、精确余额边界、命令原子性、预览只读、空飞与改装速度、自动缺能停止、多段中转保留、补能时点/取消/刷新/离线、旧存档兼容及损坏字段。保留所有旧测试的业务断言，只调整当前存档版本和新增字段的迁移投影。新增桌面、844×390、667×375补能操作与资金不变验证。

所有合并仍必须通过类型检查、单元、根/子路径构建和零重试浏览器测试，查看截图、校验源码与ZIP后通过PR squash合并。使用既有Pages流程，发布经过验证的同一产物；没有回执不宣称上线。不得覆盖并行工作、修改仓库可见性、购买服务或上传密钥。真实设备与像素级原作验收仍未完成。

主分支abc4d17已合入按城市点击顺序规划路线的规则，本轮完整保留，不恢复单段/多段切换或航线建设费。城市点击顺序形成最多5段，解锁城市且满足现有等级/航程/状态/资金与新增能量要求即可起飞。routes只是实际运营/兼容记录，预览和失败派航不能写入记录。

## 地图城市管理按需打开

航线地图不常驻显示机场解锁/升级操作条。地图的主任务是查看网络与编辑飞行路线；地面状态仅保留紧凑的城市选择、城市详情入口、路线草稿、自动往返选项和费用/能量确认。机场解锁与升级统一在既有「机场详情」对话框中按需操作，机场目录中的详情入口保持不变。

地面规划时点击或选择未解锁城市，应打开该城市的机场详情，而不是在地图底部常驻管理按钮。若玩家从当前路线规划中解锁该城市，保存成功后关闭详情并把该城市加入原路线草稿；失败则保留详情和原草稿，不抢先显示成功。打开/关闭详情不清空已规划航段。已解锁城市仍按点击顺序直接追加。

飞行中只允许用紧凑城市选择器浏览，再按「城市详情」查看/解锁/升级；这些浏览和管理操作不能改变锁定航班的目的地、成本、收入或能量预留。此调整仅改变界面呈现，不改变机场价格、等级、存档格式、核心命令或城市通航规则。
