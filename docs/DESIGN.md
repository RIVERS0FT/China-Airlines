# 中华航空 · v0.4 点击顺序路线修订

状态：机场目录、独立候机大厅、到离港信息、锁定航班收支与机队运行清单继续保留；本轮将航线地图改为《中华铁路》式「按城市点击顺序组成路线」，并取消独立的航线建设玩法。不将当前版本称为完整复刻。

## 1. 本轮规则覆盖与冲突处理

此前 [ARCHIVE-V0.4-CREW.md](ARCHIVE-V0.4-CREW.md) 与 [UI-REFERENCE.md](UI-REFERENCE.md) 记录过「单段派航 / 多段计划」模式切换，以及先付费「开通航线 / 开通计划航线」再起飞。这两项与新的原作截图证据冲突。本文件从本轮起明确覆盖这些旧条款：归档文档保留历史背景，不再作为当前路线交互与航线费用的规则来源。

当前规则只有一套路线编辑流程：飞机所在城市是起点；玩家在地图依次点击已解锁城市，点击顺序就是飞行顺序。第一次点击得到一段路线，继续点击自然追加第二、第三段，不存在「单段 / 多段」切换按钮。最多仍保留 5 个航段的本作安全上限，可撤销末站或清空草稿。

机场/城市解锁后即具有通行资格，不再购买、建设或单独解锁城市之间的航线。实际是否可飞仍由机型航程、两端机场等级、飞机状态与运营资金决定。路线预览不扣费；每段只在实际起飞时扣对应运营成本。旧存档中的 `routes` 字段继续兼容保存，但只作为既有航迹/自动值勤技术索引，不代表需要付费解锁的玩法资产。

## 2. 设计继承与边界

机场浏览详细交互按 [AIRPORT-BROWSING.md](AIRPORT-BROWSING.md) 执行；地图相机继续遵循 [MAP-LAYOUT.md](MAP-LAYOUT.md)；客货队列继续遵循 [UI-REFERENCE.md](UI-REFERENCE.md) 中未被本文件覆盖的部分。[FLIGHT-OPERATIONS.md](FLIGHT-OPERATIONS.md) 继续规定当前航班锁定账目、运行状态筛选及只读导航。

默认仍跟随选中飞机；玩家主动进入机场时切换为固定机场浏览。无当地停靠飞机时显示空停机坪和只读客货，不能借用其他机场或在途飞机。实际起飞始终从飞机真实停靠机场开始，浏览目标不能瞬移飞机。

完整复刻范围仍以 [REPLICA-COVERAGE.md](REPLICA-COVERAGE.md) 和 [REPLICATION-MATRIX.md](REPLICATION-MATRIX.md) 的证据—实现—差异清单核对。原作封存、拆解组装、能量消耗、关闭站点等不得因现有售机或运营成本已经实现而标记完成。

## 3. 不变约束

横屏、中文、2D、单机 Web/PWA，TypeScript + Vite + React + PixiJS 8 + Zustand + Dexie。无业务后端、账号、外部地图、在线字体、广告或遥测，运行素材原创。

`src/core` 是经营状态唯一写入者；地图和预览只读快照。保留真实客货、最终目的地单次交付、8 秒周转、最多 5 段有限路线、真实供给驱动自动值勤、安全售机、历史机队任务、最多 8 小时事件式离线推进和时间回拨规则。动画、浏览和路线草稿不付款、不补客源。

包版本仍为 0.4.0，存档格式 4，IndexedDB 结构 1，依赖和锁文件不变。本轮不新增存档字段：旧版已记录航线不收费重置、不删除；新航段首次实际使用时自动记录技术索引。导入失败不得覆盖有效存档，事务备份/revision 并发保护不变。

## 4. 当前操作流程

装载客货 → 打开航线地图 → 依次点击城市形成 `起点 → 1 → 2 → …` 草稿 → 查看逐段用时、运营成本与交付 → 确认起飞。点击未解锁城市时先执行城市解锁；解锁成功后该城市可直接加入路线。单站路线可选择自动往返，但仍要求随航调度员、真实直达订单和既有自动值勤安全约束。

地图点击、下拉键盘选择均进入同一顺序编辑函数；下拉只是无障碍/键盘备用入口，不形成第二套路线模式。飞行中的地图保持只读浏览：更改浏览城市不改变已锁定的目的地、成本或交付收入。

## 5. 验收

单元测试必须覆盖：已解锁城市无需 `route` 购买即可直接派航；多段路线不需要预开任何边；预览零建设费；自动值勤可直接选择满足机型条件的已解锁城市；旧存档 `routes` 仍可验证和续跑。

浏览器测试必须覆盖：页面不存在「单段派航」「多段计划」「开通航线」「开通计划航线」操作；依次选择武汉→北京→上海得到同序 3 段草稿；撤销末站/清空路线有效；解锁新城市后可立即加入路线；桌面 1440×900、手机横屏 844×390 仍可确认起飞且地图可读；飞行中锁定账目不受浏览选择影响。
