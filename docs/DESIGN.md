# 中华航空 · 当前设计

## 产品与架构

本项目是航空版《中华铁路》式单机经营游戏：保留场景装载、真实客货、顺序选路、载具成长和到达结算的操作习惯，使用原创素材，不复制参考游戏的商标、图片、音效或代码。未取得原作证据的数值均明确作为航空化适配，不宣称完整一比一复刻。

`src/core` 是经营状态的唯一写入者，不依赖 DOM、React、PixiJS、Three.js 或数据库。UI 只发送命令；机场、地图和飞机场景只读状态快照。到达、周转、补能、生产和离线推进都由时间事件结算，不使用动画回调，不允许重复结算。

## 运输经济

球面两机场的大圆距离为 `km`，航空版距离单位为：

```text
D(a, b) = floor(km(a, b) / 4)
```

普通旅客和货物订单的基础收入为：

```text
订单基础收入 = 数量 × (D(始发地, 最终目的地) + 50)
```

服务类型只决定订单表现和专业货舱条件，不改变金币倍率。自有生产物资运费为 0。

设编队等级为 `G`，进化等级为 `L`，进化倍率为：

```text
J(0) = 1
J(L) = 1 + 1.02^L / 100，L >= 1
```

同一站点本次交付的运输收入为：

```text
收入 = floor(该站交付订单的基础收入总和 × 2^G × J(L))
```

没有满载奖励，也不检测是否满载。装载更多订单只通过订单基础收入总和自然增加收入。

设一条已确认运输计划的实际航段距离单位之和为 `D路线`，强化后的重量、速度为 `W`、`S`，有效舱段数为 `N = 1 + 容量改装等级 + 职业扩舱等级`：

```text
路线运行成本 = floor(D路线 × W × S × 2^G × N / 400000)
```

成本不强制最低 1 金币。多段计划使用累计成本差分分配每段扣款，因此所有航段扣款之和严格等于整条路线只取整一次的结果。订单收入始终按始发地到最终目的地计算；绕行只增加运行成本。

```text
净利润 = 各站实际交付收入之和 - 路线运行成本
```

净利润允许为负。报价是只读投影，只有成功起飞才扣除该航段成本；抵达只结算已锁定的交付收入。

## 客货、航班与离线事件

- 新订单代表 1 位旅客或 1 单位货物，具有固定始发地、最终目的地、位置和基础奖励。
- 装卸移动同一个订单对象，不复制订单。中转不付款；最终交付后删除订单并只记录一次统计。
- 最多规划 5 段。计划保存路线总成本契约，后续航段按同一契约结算。
- 飞行起点与终点、出发和到达时间、成本、收入及载荷在起飞时锁定。
- 离线推进上限 8 小时；墙钟回拨不倒退模拟时间。主动导入只恢复模拟状态，不根据文件年龄发放离线收益。

## 存档与持久化

当前且唯一支持的保存格式为 `version: 10`，IndexedDB 结构版本为 1，两者独立管理。导入只接受字段集合、枚举、数值范围、引用关系、订单、人员、航班、能量和路线成本契约全部有效的当前存档。

版本不符、未知机型、未知机场、额外或缺失字段、非法数字及引用不一致都会拒绝。失败导入不得替换主存档或备份。保存时在同一事务中轮换上一份有效主存档到备份，并使用 revision 防止多标签页陈旧写入。

仓库不保留旧格式迁移代码、冻结目录、历史测试夹具或旧版设计规范。格式改变时直接更新当前设计、验证器和测试；不自动猜测或改写不兼容文件。

## 视图与资源边界

- 页面共用全局骨架和底部一级导航；任务、设置、帮助和详情使用临时浮层。
- 航网采用离线球面投影和本地地形，不调用在线地图、字体或遥测。地图只读状态，不结算收益。
- 飞机剖面与完整外观使用同原型、姿态、尺度、基线和原创蓝白金涂装；现实资料只决定相对级别，游戏容量不是现实吨位或座位换算。
- UI 缩放、语言和页面浏览状态独立于经营存档，不得通过视图行为修改核心状态。
- 所有当前细分规则必须与本文件一致；发生冲突时先更新本文件，再修改代码和测试。

## 验收与交付

每次规则修改必须运行类型检查、核心与持久化测试、根路径与 Pages 子路径生产构建，以及完整 Playwright 流程。浏览器流程覆盖桌面横屏、两种手机横屏、竖屏提示、刷新恢复、导入导出、离线启动和关键经营链路。

未运行或失败的检查必须明确记录。功能分支通过 PR squash 合并；日常修改使用仓库既有部署路径，不重复生成 ZIP。只有实际部署成功并验证目标端点后才能宣称上线。
