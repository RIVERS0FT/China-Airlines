# 中华航空 · 复刻方向设计 v0.2

状态：机场装载与订单运输第一阶段。用户已明确目标为航空版《中华铁路》，不是通用航空管理后台。v0.1 的地图首页、按班次凭空生成载荷与此目标冲突；本设计替换这些规则。旧设计存于 ARCHIVE-V0.1.md，仅供迁移参考。

## 1. 产品与复刻边界

以原作的场景构成和操作习惯为参照：机场装载 → 航网选择 → 确认起飞 → 飞行场景 → 到达交付 → 切换飞机继续经营。顶部资源、中央大载具、下方客货、两侧切换和底部功能入口是本轮布局基准，不保留管理侧栏作为主要入口。

全部飞机、航站楼、客货图标采用本项目原创矢量绘制，不拷贝原作商标、人物、美术、音效或代码。参考截图只作研究，不加入运行资源。参考：此前确认的车站装载截图 https://cdn.ourplay.net/xspace/news/1638343026337334.jpg 。其版本未固定，不能声称像素级或规则完全一致。

本轮范围：真实客货池、选择装载、卸载中转、最终目的地结算、以真实供给驱动的自动往返、v1→v2 存档迁移，以及机场/航网/飞行三类界面。12 座机场、3 种虚构客货机、16 架上限和4项任务沿用既有配置。纯客/货机分类、改装、机库容量养成、多段预设计划、完整原版数值和新手分步高亮未实现，不放置无效占位按钮。

## 2. 工程约束

横屏、中文、2D、单机 Web/PWA，无账号、业务后端、外部地图、在线字体、广告或遥测。保留 TypeScript、React、Vite、PixiJS 8、Zustand、Dexie。

src/core 是经营状态唯一写入者；UI 发命令并读快照，不能在动画结束时发钱。地图保留 PixiJS/WebGL；机场与飞行侧视使用本地 SVG/CSS，无网络图片请求。飞机座椅图表示容量比例，不是一图标对应一真实座位。减少动态效果偏好下关闭背景动画。

legacy.ts 固定 v0.1 校验与迁移基线，不是第二个运行核心。v2 复用旧校验器校验公共基础字段及飞行几何，其旧收入公式只用于校验投影，不参与 v2 结算。修改迁移基线须新增固定样本测试。

## 3. 订单与供给

订单字段：id、kind(passengers/cargo)、from、to、amount、reward、location、createdAt、expiresAt。location 是唯一位置，必须为机场代码或飞机 ID。同一订单不能同时在两处。来源和最终目的地在生成后固定。

开局北京和上海各补至12单，此后模拟时间每120秒对全部已解锁机场补至12单；机场解锁也触发补充。只向已解锁的其他机场生成需求。确定性序号决定目的地轮换及种类：每第三单货物1吨，其余旅客15或20人。已有机场等待订单达到12单则不新增；含中转在内最多24单。数值是本轮可验证基线，不宣称等于原版数值。

未接受订单有效期360秒，过期时删除；刷新与过期均是时间事件，不能通过刷新页面或点击按钮提前刷新。第一次装机后 expiresAt=null，此后无论在飞机或机场中转均不会过期。容量单位和显示单位一致。

每单报酬：旅客 round(人数×(100+原始距离×0.18))；货物 round(吨数×(300+原始距离×0.4))。收益锁定，不因为中转绕路增加。v1 合并舍入迁移的最后一项可能与单独舍入差1币，校验允许这1币差额。

## 4. 装载与中转

load：飞机必须停靠、完成周转、关闭自动往返，订单必须位于同一机场。分别核对座位/货舱，整单装载，容量不足不拆单、不部分修改。
unload：同样限制飞机状态，订单必须在该飞机上，机场等待区不得超过24单。卸下不付款，保留原始去向、报酬和订单 ID。
load-destination：按当前队列顺序装载指定最终目的地且放得下的整单，跳过不合容量的订单；不会生成需求或瞬移异地订单。

支持手动经停/转运：北京→上海订单可先飞武汉，继续留在机上，或卸至武汉再由另一架飞机运到上海。中间航段只扣运营成本、不付款；到达最终目的地自动删除该订单并且付款一次。统计客货量按最终交付计，不按中转航段重复累计。

## 5. 派航与自动往返

机场解锁/升级、购机价、航程、速度、最低机场等级、航线开通费沿用 catalog.ts。起飞必须从飞机实际停靠位置出发，校验航程、航线、两端等级、周转和资金。单程时长=max(30,ceil(距离/速度×45))，成本=round(500+距离×每公里成本)。起飞时扣成本；锁定机上载荷和本段应交付金额。允许空机调机，界面二次确认，并明确零收入和负净收益。

到达后8秒周转。关闭自动往返不取消已起飞航班。自动模式仅接受当前所装订单全部直达的首航；返程按同样容量规则装载真实队列。无可装载订单则等待下一次供给刷新，而不是空载反复起飞或虚构收入。资金不足停止自动，已装订单留在地面飞机上。手动停止等待中的自动模式后，最多保留8秒地面就绪时间。

## 6. 时间和存档

离线推进最多8小时，以事件跳转推进，不逐帧补跑。超出时间永久丢弃；时间回拨推进0秒并重新对齐。时间输入必须有限且在0..8.64e15毫秒范围。相同时间先处理供给刷新/过期，再按机队数组顺序处理到达或自动出发；订单序号、队列顺序和事件优先级必须使分步与整段推进得到相同快照。

保存格式 version=2，新增 orders、nextOrderId、nextDemandAt。数据库结构仍为1（对象仓库未变化），两个版本互相独立。导入限1MB UTF-8；精确字段、引用、唯一ID、位置、容量、报酬、时间、飞行清单和统计均须验证，未知版本拒绝。

v1先严格验证再迁移：保留资金、机场、机队、航线、任务、统计、原时间锚点和在途时刻。旧航班按锁定人数/货量生成机上订单，合计报酬严格等于旧航班收入，不能重新计价或丢失。迁移后正常启动仍按旧锚点补算；主动导入/备份恢复重新锚定到当前时间，不领取文件时间的离线收入。v2不重复迁移或补发订单。

继续使用事务性主存档/上一份备份和revision比较交换。先校验候选并保存成功，再替换导入后的核心；失败不覆盖有效进度。每10秒、关键操作、页面可见性改变时检查点保存。浏览器关闭时异步写入不保证完成，不能替代导出备份。

## 7. 横屏与交互

桌面参考1440×900、1280×720；手机覆盖844×390与较窄横屏。顶部资源与保存，中部机场牌/飞机状态/客货容量，中央机场或飞行场景，下部可横向滚动的客货卡，底部导航和起飞按钮。机队/商店/任务采用居中弹窗；飞行中能切换其他飞机，不能装卸当前航班。

航网使用全幅地图、上部经营预估、下部目的地和起飞操作，不以常驻右侧管理表单为主要结构。地图初始化失败时仍保留下拉目的地及所有文字操作。原生按钮/选择器/对话框保留键盘、焦点和关闭功能；竖屏提示而非强制锁方向。
