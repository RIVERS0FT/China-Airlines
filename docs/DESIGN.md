# 中华航空 · v0.5 基础能量预算

本轮从界面补齐转向实际运营约束：按已读取的2016年攻略记录“飞行每分钟消耗1点”的比例，新增能量预留、不足停止与地勤补能。并未完成原作全部数值复刻。

## 设计冲突与继承

旧版只检查运营资金、航程和机场等级，可以在有供给时一直自动飞行。本轮明确替换这一无限连续运行规则；除 [ENERGY.md](ENERGY.md) 的能量条款外，完整沿用 [ARCHIVE-V0.4-ROUTES.md](ARCHIVE-V0.4-ROUTES.md) 及其引用的人员、机场浏览、航班运行和经济规则。不能把界面禁用当作核心已实施限制。

默认240点容量取自旧攻略的一个示例，并非确认所有原版车型都是240点。120秒免费地勤补满、按秒预留和取消规则是航空化暂定设计；没有查明原版恢复时点、费用及不足一分钟的舍入，必须在界面和数值档案中明确，不擅称等价。暂不添加未经核实的原版付费货币。

## 运行与兼容

包版本0.5.0，存档格式5，IndexedDB结构仍1；依赖版本不变，lockfile只更新根包版本。每架飞机有独立可用能量、当前航段预留量和补能截止时刻。唯一写入者仍为src/core；UI只显示数据并发送命令，不用动画或计时器回调扣能。

手动、自动、多段全部经过同一depart入口检查并预留。余额不足时当段不能起飞或扣钱；已有在途航班正常抵达。后续计划或自动值勤遇到不足，在实际机场停止，保留已装载订单。补能需完成周转、停止值勤和取消后续计划；完成前不增加能量，取消也不补。补能不是飞行，不产生运输收入、不消耗或清空客货。

冻结v4校验器和catalog-v4。旧版v1—v4先严格验证再迁移到5；旧资金、订单、改装、时刻和已锁定航班不重算，每架旧机赋满初始预算，当前旧航班豁免追扣。只有今后起飞才预留。v5读档不能重复赠能，非法或缺少字段拒绝且不覆盖有效进度。

默认只显示目的地、预计时间、净利润和成本四项读数；地图直接延伸到页面底部。城市选择由顶部目的地按需打开，路线/能量/自动往返由“查看路线”按需打开。左下缩放与路线后退/撤销/取消/查看，右下唯一“检票起飞”；当飞机在途，返回按钮明确叫“返回航班”。错误和存档冲突保留，正常通知不占发航地图。

取消返回进入前的实际飞机或固定机场，不瞬移、不卸货、不撤销已保存的解锁，也不取消在途航班。地图保持挂载，弹窗不重置草稿和相机。隐藏其他飞机只改变渲染；航程圈围绕末站提示但所有可飞判断仍由核心执行。

三种视口的地图高度至少为85%，主要点击区不小于44像素。回归测试改用新的真实入口，经营/存档原断言保留。包0.5.0、存档5、核心/运行控制器/持久化/依赖不改。通过截图与全量测试后按既有约定打包、squash合并、部署。

## 乘客目的地地图标注

规划路线时，发航地图读取当前飞机的已装载订单，并仅对 `kind === passengers` 且 `location` 为当前飞机 ID 的订单按目的机场汇总。在对应机场旁显示高对比“乘客 N”徽标，N 为该目的地机上旅客人数；货物、其他飞机订单和仍在候机大厅的订单不参与标注。

该标注是纯 UI 只读投影，不修改订单、草稿、航程判断、派航条件或存档，也不新增后台状态。装卸或交付造成机上乘客变化后标注随最新快照更新；当前飞机没有已装载乘客时不显示任何乘客目的地徽标。
