# 中华航空 · 当前设计

## 页面架构统一（2026-09-16）

页面结构以 [UI-ARCHITECTURE.md](UI-ARCHITECTURE.md) 为准。本增量明确替换原先机场目录、机队管理、飞机商店、经营中心使用全屏大弹窗的呈现方式：它们现在与公司组织一样属于一级工作页，共用全局骨架和底部导航；任务、设置、帮助和机场详情继续为临时模态浮层。

主分支包含 DA40 更新的原设计全文原样保存在 [ARCHIVE-DESIGN-2026-09-16.md](ARCHIVE-DESIGN-2026-09-16.md)。除本次明确替换的 UI 容器与页面导航条款外，其中全部经营、存档、资源、美术、迁移、离线和交付规则继续有效；该档案内部仍按从新到旧的增量优先级解释。不是重置游戏设计，也不删除历史规范。

## 飞行场景复用开始页面动画（2026-09-16）

开始页面与真实在途飞机共用 `flight-motion.css` 中的同一组巡航关键帧、6秒周期和缓入缓出曲线：轻微浮动与俯仰，远近云层继续共用 `FlightSky` 的32秒/18秒视差漂移。动画只作用于飞机内部展示层，外部定位、点击区域、航班进度和收支文字保持固定；不把开始页面的通用飞机图片替换到玩家的实际机型上。飞行展示使用完整视口并预留巡航位移边距，不沿用会裁掉 DA40 机尾的紧裁切视口；整个动画周期内完整机型图保持在场景内。地面剖面及球面地图3D飞机不套用此装饰动画。

飞机动画只在真实 `plane.flight` 存在时启用；到达后恢复地面剖面。系统“减少动态效果”同时关闭开始页面及飞行场景的飞机、云层动效，恢复偏好后可继续播放。动画不发出经营命令，不控制起飞、到达、扣费或结算；导航、刷新、离线缓存和UI缩放边界保持。

## 并行机型更新兼容

完整保留主分支 DA40 目录、1客0货不可扩容规则、v6完整双图切换、现实机型参照与容量文案，见 [AIRCRAFT-REALISM.md](AIRCRAFT-REALISM.md)。当前商店13种可购机型，初航赠机不变；不能因页面重构退回12种或丢失新增资源。核心与持久化相对该主分支不变。

## 不变边界

- 场景式航空运输经营，不改为通用后台；地图、机场剖面、组织树保留各自表现。
- `src/core` 仍是经营状态唯一写入者。导航、页签、滚动和弹窗不得写入或结算经营数据。
- 游戏存档9、IndexedDB结构1、所有核心命令、经营数值、真实客货、在途收益与旧存档拒绝规则不变。
- [DISPLAY-SCALING.md](DISPLAY-SCALING.md) 的同有效比例、同 UI 缩放使用同逻辑布局保持；安全区由物理外层统一处理。
- [MAP-BROWSE-CHROME.md](MAP-BROWSE-CHROME.md) 的浮动导航、空白穿透和实际控件标签避让保持；不恢复工具行或缩放按钮。
- [AIRCRAFT-CABIN.md](AIRCRAFT-CABIN.md) 与 [UNIFIED-AIRCRAFT-CANVAS.md](UNIFIED-AIRCRAFT-CANVAS.md) 的真实机内装载、统一画布和新双视图规则保持，不添加独立客货卡片或第二内部视图。
- 单语言标题、机场代码隐藏、顶部点券只读、装卸静默反馈、地图3D飞机与离线缓存保持。

## 验收与交付

类型检查、核心与持久化测试、根/子路径生产构建、零重试 Playwright 流程均需通过。新增工作页可达性、导航位置、主滚动区域、弹窗焦点恢复、缩放和页面返回状态的验收。不得用删掉业务断言来适配新的页面结构。完整浏览器回归在每种路径下分为两个独立分片，共四个验证任务；每片仍为单 worker、零重试，不设置用例过滤，四片全部成功才完成验收。分片只缩短单任务运行时间，避免测试完成后的报告上传及收尾触及20分钟时限，不改变测试集合和单用例超时。

在功能分支开发，通过 PR squash 合并；同步检查并行主分支变化。沿用既有 Pages 自动部署，不生成源码或静态 ZIP；没有成功部署回执不得宣称上线。未执行的检查与实际设备验证必须如实标注。
