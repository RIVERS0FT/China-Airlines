# 中华航空 · 航空化复刻设计 v0.3

状态：机型分工、机库养成与有限多段运输计划。承接 v0.2 场景和真实订单，不回退为管理后台。旧设计见 ARCHIVE-V0.2.md；v0.1 只供历史迁移参考。

## 1. 参照与阶段边界

目标仍为航空版《中华铁路》：场景式装载、地图安排运输、载具经营与网络扩张。全部航空场景、飞机、人物和图标为本项目绘制，不复制参考游戏的素材或代码。

本轮查阅原作 App Store 的开发者说明（https://apps.apple.com/cn/app/中华铁路/id885305981）和运营平台《新手玩家初级攻略》（2018-02-26，https://news.7k7k.com/content/20180226/915597.html）。后者涉及纯客/纯货车的搭配和车库扩张，开发者回复提到升级增加车厢、司机自动装货。这些只能确认玩法方向；不能证明本轮改装倍率、价格、航段上限是原版数值。

本轮实现：三系列九种机型、纯客/纯货/混合分类、四项三级改装、机库机位扩建、最多五段运输计划及 v1/v2→v3 迁移。飞机不能像列车那样加挂车厢，因此把容量养成转换为舱位扩充。司机雇用、出售/退役、联盟、联网经济、新手分步高亮、全部原版数值与像素级界面对照尚未完成。不放置无效占位按钮。

## 2. 不变架构

中文、横屏、2D、单机 Web/PWA；无账号、业务后端、外部地图、在线字体或遥测。TypeScript + Vite + React + PixiJS 8 + Zustand + Dexie/IndexedDB。src/core 是经营数据唯一写入者。UI 发命令，场景和地图只读快照；动画不发钱。

legacy.ts 与 legacy-catalog.ts 固定 v1 校验/迁移参数；save-v2.ts 固定 v2 校验，不作为第二个模拟核心。旧型号的原始参数保留。v3 校验公共基础字段时投影到 v1 基础校验；真实飞机、改装、容量、在途航班及计划均独立严格检查，不拿投影结果结算。

## 3. 客货订单与装卸

沿用 v0.2：每单有独立 id、kind、from、to、amount、reward、location、createdAt、expiresAt。唯一位置为一个机场或一架飞机。每120模拟秒向已解锁机场补至12单，等待区最多24单；未接受订单360秒过期，第一次装载后永久保留。确定性序号轮换目的地，每第三单货物1吨，其他单旅客15或20人。不会因起飞/刷新页面生成需求。

报酬按原始起终点锁定：旅客 round(人数×(100+距离×0.18))；货物 round(吨数×(300+距离×0.4))。绕路不增价，只在最终目的地付款并删除订单一次，统计按最终交付累计。旧 v1 合并舍入迁移允许最后一单1币差额。

逐单装/卸和同目的地整单装载检查飞机在地面、周转完成、无自动往返或后续计划。客货容量独立。纯客机不载货，纯货机不载客。不可拆单、重复装载、瞬移或越过上限。卸载只改变位置，不付款。允许手动经停和换机中转。

## 4. 机型、改装和机库

catalog.ts 为现行机型和价格的唯一配置来源。旧 lark/swallow/horizon 三种混合机参数不变；新增各系列 P/F 型，三类各三种，共九种。纯客初始容量90/190/330人、零货舱；纯货初始容量8/24/50吨、零座位。全部为虚构航空数值，不是现实航机资料。

每架飞机独立保存 upgrades：capacity、engine、range、efficiency，均为整数0..3。一次改装费=round(机型基础价格×0.12×(该项当前等级+1))，即时扣费和生效。只能在地面、周转结束且无自动运输时改装；已有订单保持身份、数量和报酬。在飞行中的参数不可改变。

- 舱位：座位=floor(基础座位×(1+0.1×等级))；货舱=基础吨位+ceil(基础吨位×0.1)×等级。零容量仍是零，类型不能借改装转换。
- 发动机：速度参数=round(基础速度×(1+0.05×等级))。
- 航程：单段最大距离=round(基础航程×(1+0.1×等级))。
- 节能：每公里成本=基础成本×(1-0.05×等级)。最终单段费用统一舍入。

aircraftSpecs 统一计算界面、容量校验、航程、耗时和成本；不持久化派生属性。资金不足、未知项目、满级、飞行中或自动计划中均不扣费。

新游戏4个机位，每次扩建2位，费用=40000+(当前机位-4)×15000，最高16位。购买同时校验资金、交付机场等级和剩余机位；无退款/售机。旧存档迁移机位=max(4,ceil(已有飞机数/2)×2)，不得删除旧飞机或追收扩建费。

## 5. 单段与自动往返

保留机场最高3级、升级费=当前等级×60000、机场解锁价和航线费=2500+距离×5。航线双向共享，重复开通不扣费。起飞校验实际位置、已解锁两端、机型最低机场等级、当前改装后航程、已开航线、周转和运营资金。

单段时间=max(30,ceil(距离/有效速度×45))秒；单段成本=round(500+距离×有效每公里成本)。起飞即扣成本，锁定载荷和本段交付收入；到达按已锁定收入结算。空机允许调机，界面明确确认零收入和成本。

到达周转8秒。自动往返只接直达且有真实供给的订单；无供给等下次补充。资金不足停止自动并保留客货。停止自动不取消在途航班。自动往返与多段计划互斥。

## 6. 多段运输计划

地图上切换“多段计划”，选择机场后添加，支持撤销末段、清空，最多5段。草稿只存UI，未确认不改变经营状态。允许回到之前的机场，不允许相邻相同机场。每段独立受航程限制，而非全程距离之和；不隐式穿越未开放机场。

planQuote 一次检查所有段，列出逐段成本、预计时间、首次交付收入和未开通线路费用；重复线路只计算一次建设费用，重复到达同一目的地也只计算一次已装订单收入。预计总时间包含中间8秒周转，不包含末站周转。

“开通计划航线”先完整验证再一次扣除所有缺失线路费用，逐条添加唯一双向线路；失败时资金和线路不变。“执行运输计划”要求全部线路已开通，校验全部航段后支付首段费用并起飞。只需首段可支付，不预扣后续总成本；界面明确标注。

保存的 itinerary 仅为未起飞的后续目的地数组，长度0..4；当前段保留在 flight。到达先交付该站订单，其余留机，8秒周转后启动下一段并移除其队首。途中不自动装新订单，不刷新客源，不无限循环。后续费用不足或条件不满足时清空剩余计划、停留当前机场、写入原因，保留所有未交付订单。

“取消剩余计划”只移除未起飞段；当前航班及已扣成本、锁定收入均不变。在地面周转时取消也不会跳过周转。最后一段已起飞后没有可取消的未来段。进入新单段或手动装卸前必须先取消后续计划。

## 7. 时间、存档和迁移

离线最多补算8小时，以事件时间跳转，超出部分永久丢弃；回拨推进0秒并重置墙钟锚点。输入时间必须有限且为0..8.64×10^15毫秒。相同时刻先刷新/过期，再按机队顺序处理到达、自动或计划起飞。分步与整段推进结果应一致。

保存格式 version=3，新增 hangarSlots 和每架飞机 upgrades、itinerary；数据库结构仍为1（对象仓库不变）。包版本为0.3.0，区别于存档格式。v1先通过冻结校验，按原在途人数/货量/收入生成真实订单；v2通过冻结校验后添加零级改装、空计划和兼容机位。所有迁移保留资金、机场、航线、统计、订单位置与ID、原时间锚点和在途锁定收入，不重复迁移。

主动导入及备份恢复重新锚定本机时间，不领取文件旧时间的离线收益；正常启动保留墙钟差供补算。JSON上限1MB UTF-8，未知版本拒绝。严格校验精确字段、唯一ID、有效引用、时间、容量、改装等级、机位、后续线路及在途实际参数。校验失败不覆盖内存或数据库中有效存档。

继续事务主存档/备份、revision比较交换和多窗口冲突保护。每10秒及关键操作检查点保存；导入先候选验证、保存成功后替换核心。浏览器关闭异步写入不保证完成，仍须导出备份。

## 8. 布局与验收

机场大载具、下方可滚动客货卡、左右切机和底部操作沿用。纯货机侧视显示货舱而非座椅，零容量不产生NaN比例。卡片显示不可装载原因。商店分类页签加2列商品卡；机库弹窗显示机位、飞机选择、机体预览及四项改装，不占主场景。地图计划通过航段筹码、撤销和下方确认完成，展示后续目的地与取消入口。费用明细可折叠，逐段显示时间、运营成本、最终交付收入及建设费用；复用同一双向航线时标明不重复收费。计划模式顶部显示全程估算，不混用当前候选机场的单段估算。手机横屏收起明细时保留至少90像素地图高度，完整细节可在明细区滚动查看，确认与底部导航仍可操作。

桌面1440×900/1280×720；横屏844×390及较窄横屏，原生可滚动弹窗；竖屏提示。保留键盘焦点和文字替代入口，无外部运行资源。

运行类型检查、全部单元测试、锁定依赖构建、根路径及 /China-Airlines/ 子路径零重试浏览器验收。新增覆盖纯货采购/装载、改装与扩建、计划执行/取消/刷新恢复、v2导入，以及手机横屏入口可达。测试失败必须修复后再合并，不以重试掩盖。截图用于人工复核，不代表真实手机或iOS认证。

在功能分支通过PR squash合并，交付源码/静态ZIP、报告、截图和校验值。按既有Pages流程先完整复验再发布同一产物。站点未配置则记录阻塞，不改变私有可见性、不购买服务、不上传密钥；没有成功回执和可访问网址不能宣称上线。
