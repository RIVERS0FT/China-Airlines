用户明确要求“选择航线按钮放右下角”“客货区不要用卡片形式”“去掉一位货物胶囊”。因此本文件覆盖 `RAILWAY-INSPIRED-UI.md`、`AIRPORT-MOBILE-GAME-POLISH.md` 中的卡片与抬高/宽横向主按钮描述；原有经营、存档与路线规则继续以主设计为准。

- 客货以独立人物或货箱置于连续地面，按目的机场分组，每组左侧共用一个独立站牌，客货排在该站牌右侧，个体仅显示报酬和操作状态，不使用外框或卡片底色。悬停仅强调主体，键盘焦点保留清晰描边。
- 新订单数量为1时不重复显示类型/数量胶囊；按钮无障碍名称仍含准确数量。旧存档中数量大于1的聚合订单保留“历史旅客组/历史货单”及实际数量，不拆单、不改变运费。
- “制定路线”完整放在页面右下角底部导航行，使用正常布局而非向上浮动；客货区恢复全宽，翻页箭头到达队列右侧。禁用时给出没有本场飞机、在途、周转、补能或保存中的真实原因。
- 任务牌显示已有任务定义与真实进度；航班、改装、奖励快捷入口分别打开已有航班运行、机库、任务面板。只读机体容量叠层始终显示，删除“显示客货”按钮，不改变机上订单。
- 删除场景中重复的机场名称与代码，顶部机场状态保留。
- 删除底部“开始起航引导”按钮及其下方说明。首航任务牌根据真实进度提示装载、规划、观察到达、领取奖励；任务详情提供前往装载、规划首航、查看航班入口。任务奖励仍调用已有领取命令，不自动派航或增加奖励。已有帮助内按需分步引导保留，旧存档的引导状态保持兼容。
- 机场开放数量仍可在机场目录查询；离线与存档能力不变。

## 客货原位装卸

删除“候机大厅／机上客货”、分类、补客倒计时、目的地选择器构成的工具行。停靠时统一显示当前机场待运订单和当前飞机已装机订单，按目的地分组，同组按创建时间和订单编号稳定排列，装机/卸载不会让订单跳到其他列表。未装机显示“点击装机”，已装机显示“已装机 · 点击卸载”；飞行、补能、周转或容量不足等原因沿用核心约束。

目的地站牌可点击执行该目的地的现有批量装机命令。点击飞机只定位到已装机订单，不切换清单；底部“机场装载”回到完整客货区。飞行中隐藏整个客货区，飞行场景自动扩展，锁定航班收支移入飞行场景；点击飞机打开航班运行面板。到达后恢复客货区，交付订单正常消失、留下中转订单。经济、存档和离线补客规则不变。

右下角原“选择航线起飞”统一重命名为“制定路线”，仍只进入路线规划，实际派航继续由地图中的检票起飞执行。

站牌分组只改变显示顺序，不改变订单ID、装卸命令和数量。分组按首次出现的目的机场顺序排列，同组按创建时间和订单编号稳定排列；路牌随所属目的地组横向滚动，不同目的地分别绘制路牌，装卸或交付后按现存订单重新分组，空分组不保留站牌。

客货区使用原创候运地面背景，包含铺装、安全线、路缘灯与深色报酬显示区域。隐藏原生滚动条，仅改变外观，保留触摸滑动、左右按钮和键盘滚动。

## 手机横屏高度预算（2026-09-13）

844×390、667×375 等手机横屏不再沿用“客货区132px + 底栏60px”的固定高度组合。机场主页在宽度不超过950px且高度不超过480px时使用视口比例预算：顶部 HUD 约12%、客货区约28%、底部导航约13.5%，中央机场场景自动占满剩余空间，目标不少于约44%的视口高度。实现使用 `dvh + clamp()`，避免不同手机浏览器工具栏造成固定像素比例失真；桌面、竖屏提示和独立发航页不应用该规则。

客货区压缩只减少人物/货箱画布和上下留白，不缩小目的地站牌、左右翻页等主要触控目标；主要操作保持至少44px。底栏同样优先压缩图标和内边距，“制定路线”继续位于底部导航正常布局，不向上悬浮、不遮挡客货。机场场景获得的新增高度用于完整展示飞机和地面，不修改飞机命中区域、客货容量投影、装卸规则或核心状态。

浏览器回归必须直接测量 `.game-hud`、`.scene-wrap`、`.apron-queue` 与 `.game-dock` 的实际高度：844×390 与667×375下机场场景不得低于视口44%，客货区不得高于30%，底栏不得高于15%；主要队列/导航按钮保持至少44px，页面不得产生水平溢出。1440×900桌面布局保持原比例。
