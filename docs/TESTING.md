# 测试分层与编写约定

测试通过的依据是功能结果：实际金额、订单身份与位置、容量、运行状态、权限、时间事件及持久化结果。文字可以用于寻找控件、核对翻译或说明拒绝原因，不能单凭“出现某个词”宣称经营功能通过。

## 分层与执行入口

| 层级 | 目录 | 命令 | 通过依据 |
| --- | --- | --- | --- |
| 单元功能 | `tests/unit/` | `npm run test:unit` | 计算函数、单项命令和只读投影的数值、状态、边界与失败原子性 |
| 跨模块流程 | `tests/integration/` | `npm run test:integration` | 真实 GameCore、时钟、序列化及 SaveRepository 协作；连续经营和主备份 |
| 资源完整性 | `tests/assets/` | `npm run test:assets` | PNG 解码、尺寸、透明度和唯一性；不作为玩法覆盖 |
| 完整游戏流程 | `e2e/flows/` | `npm run test:flows` | 生产新开局，通过真实界面操作并检查导出的经营状态 |
| 浏览器功能 | `e2e/functional/` | `npm run test:ui`（含下项） | 专项功能的成功/拒绝操作及刷新联动；允许明确的场景夹具 |
| 展示与交互回归 | `e2e/presentation/` | `npm run test:ui`（含上项） | 实际布局、点击、键盘、触控、动画、WebGL、缩放、语言和资源解码 |

`npm test` 运行全部 Node 测试；`npm run test:e2e` 运行全部浏览器测试，包含完整新开局流程。分层提供开发时的定向入口，完整验收与 CI 不排除任何层级。

浏览器测试使用生产构建，先执行 `npm run build`。根路径与 `BASE_PATH=/china-airlines/` 分别构建和测试，不能使用另一条路径的旧 dist 验证。

## 编写规则

1. 按“初始条件→操作/事件→可观察结果”组织。长流程使用 test.step，使失败步骤可定位。
2. 金额、收益和订单数量校验具体值或守恒关系；不能用被测函数生成同一断言的全部期望值。
3. 负例同时验证拒绝和状态未改变；正例验证状态确实变化。仅控件可见、提示出现或没有抛错不足以判定成功。
4. 用受控时钟或 GameCore.tick 验证到达前后及重载，不固定睡眠等待航班。
5. 从实际结果取得生成的实体ID，除非初始ID本身是契约。
6. `tests/helpers/configured-game.ts` 与 `e2e/helpers/configured-airport.ts` 是已配置客货舱位的专项夹具，不能用于证明生产新开局可玩。`e2e/flows/` 的 new-company 帮助函数不注入资金/容量/存档、不覆盖 page.goto、不绕过标题入口。
7. 不读取 TSX/CSS 源码后用 toContain/正则检查函数名、标签名或单词。布局、动画与焦点由浏览器验证，业务由命令和状态验证。数据格式、翻译占位符、生成器输出、资源许可和解码仍保留对应断言。
8. 截图留证不等于自动视觉断言；界面回归仍需几何、操作和状态检查。

## 快速反馈与完整验收

单项改动先跑相关单元文件，再跑 test:flows 或对应浏览器文件。软件 WebGL 的展示回归成本较高，不应把完整两路径验收当成每次编辑后的反馈循环。最终验收仍运行类型检查、全部Node测试、两路径构建和全量浏览器；CI保留4分片与零自动重试，不能以减少断言、隐藏失败或只跑快速流程替代。

2026-09-26 本机根路径全量实测：224 项、2 个 worker，用时 502.8 秒。所有用例耗时合计约 953 秒，其中 3D 地图文件约 98 秒、导航稳定性约 68 秒；教程布局的两次失败各等待了约 30 秒。主要成本来自大量真实浏览器、软件 WebGL 场景与失败等待，而不是类型检查或断言文字。

本次修正了两个额外拖慢反馈的原因：专项夹具仍假定旧初航机的能量数值；跳过教程尚未保存完成时，存档操作已捕获即将卸载的教程按钮。前者按明确的现行机型场景断言，后者等待跳过完成并重新定位可见入口。涉及的 7 项定向复验用时 17.9 秒，全部通过。

开发阶段按改动选择 `npx vitest run tests/unit/onboarding.test.ts`、`npm run test:integration`、`npm run test:flows` 或 `npm run test:e2e -- e2e/presentation/tutorial-overlay.spec.ts`；生产代码变化后先重建对应路径，纯测试调整复用同路径的当前构建。最终再统一执行两路径全量验收。CI 沿用已有的每路径 4 分片，不在本机盲目增加 worker，避免软件渲染争抢 CPU；保留失败证据，修复后定向重跑，不用自动重试掩盖竞态。
