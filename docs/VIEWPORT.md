# 比例驱动的游戏视口与 UI 缩放

## 规则

参考现有 1440×900 桌面构图，统一设计短边为 900 个逻辑单位。

- `scale = min(可用宽度, 可用高度) / 900`。
- 逻辑宽高为实际可用宽高除以 scale。默认100%时横屏逻辑高度始终为 900；逻辑宽度仅由宽高比决定。
- 同为 16:9 的 640×360、1280×720、1920×1080 都布局在 1600×900 画布上，再整体缩放。没有手机/电脑判断、DPR 布局断点、仅放大按钮或仅缩放地图。
- 16:10 使用 1440×900；21:9 使用 2100×900。铺满视口，不把所有设备强制裁成 16:9，不拉伸飞机和图标。竖屏使用相同尺度规则并显示旋转提示，包括大尺寸竖屏窗口。

这里的比例指浏览器实际可用内容视口，而不是设备外壳的物理屏幕。地址栏、系统分屏等造成的可用比例变化会正常触发布局变化。浏览器缩放与用户无障碍偏好未被禁用；字体栅格化、原生系统选择菜单和显示清晰度可能因操作系统/DPR 而不同，不承诺跨平台逐像素相同。

## 用户缩放

「存档设置 → UI 缩放比例」提供75%–150%，默认100%，每档5%。滑杆支持方向键及Home/End；另有缩小、放大和恢复默认按钮。立即生效，刷新后记忆。

- 实际显示倍率为 `baseScale × uiScale`；内容逻辑宽高为实际可用尺寸除以该倍率，始终铺满窗口，而不是放大后裁掉页面边缘。
- 同宽高比、同用户缩放值才要求同一构图。调大时文字与固定尺寸控件变大，可见内容会减少；内容列表和长弹窗内部滚动。地图相机的经纬度与地图缩放级别不被重置，地图缩放按钮仍只控制球体视野。
- 偏好使用独立 `localStorage` 键 `china-airlines.ui-scale.v1`，不放入GameState、不派发经营命令、不更改存档格式。导出、导入、重新开始不会改变此浏览器的显示偏好。不同浏览器需要分别设置。
- 保存失败时当前打开仍能调整，并明确提示未保存。损坏值回退100%，数值限制并对齐合法档位，不会使页面缩成零或无限放大。不禁用浏览器自带缩放。

## 实现边界

`GameViewport` 使用两层容器：外层固定900短边的比例画布作为命名查询容器，仅随屏幕比例改变；内层按用户缩放调整内容尺寸及倍率。历史手机断点不会因为用户放大而重新触发，避免“调大反而缩小按钮”。组件只测量、更新 CSS 变量，ResizeObserver 响应尺寸改变，不重新挂载 App、不派发游戏命令、不写存档。`game-viewport.css` 是唯一使用真实视口单位的 UI 文件。CSS 构建插件把其他 UI 样式中的尺寸媒体查询改为命名容器查询，把 vh/vw 及其动态变体改为逻辑画布变量。原始设计值和层叠顺序不变，减少重写历史样式造成的回归。减少动画等设备偏好仍使用媒体查询；混合偏好和尺寸条件须拆成嵌套规则，避免意外恢复设备尺寸依赖。

飞机 SVG 不再因手机像素高度切换裁切框。Pixi 使用逻辑尺寸绘制，指针位置按实际 canvas 边界换算回逻辑坐标；点击机场、拖动和双指手势共享这条转换路径。客货列表跳转也把屏幕距离还原为 scrollLeft 使用的布局距离。

原生模态 dialog 位于 top layer，不继承祖先的 transform。因此所有 `dialog:modal`（包括存档设置、机场目录、城市选择、路线详情）分别使用逻辑宽高、真实视口中心和合成显示倍率；保留 showModal 的焦点约束、Escape 关闭、背景隔离和关闭后焦点恢复。

## 验收

单元测试覆盖显示偏好的限制/档位/恢复/损坏/存储失败、75%–150%下的比例不变性、异常/零尺寸、指针映射、CSS 断点与单位转换、保留 URL/字符串、设备偏好及宿主豁免。浏览器测试对比 16:9、16:10、宽屏和 4:3 的手机/桌面（不同 DPR 和触摸属性），检查机场、飞机、客货、导航、地图与两类弹窗的归一化几何尺寸；验证缩放后的真实地图点选与拖动、调整窗口、竖屏恢复、弹窗完整可见和无页面溢出。

增加上下限缩放的手机/桌面对比、设置弹窗几何与键盘焦点、真实装卸及派航后刷新、缩放偏好恢复、存储失败降级。历史“44 屏幕像素”断言改为 `44 × baseScale × uiScale`，不删除原有真实装卸、派航、焦点、存档与可见性断言。截图输出到现有 artifacts 目录；通过既有根路径和 Pages 子路径 CI 验证后才可合并。

真实 iOS/Safari、Android 键盘与刘海安全区域仍须实机验收；自动化 Chromium 不能代替真机结论。
